# 研究材料说明

本目录用于复核报告，不是可直接安装运行的产品集合。

Git 只保存作者材料、来源清单、固定提交和引用文件哈希。下列 `repos/`、`pages/`、阅读摘录、运行日志与截图是本地采集／验证缓存，不随克隆分发。没有缓存也能生成报告并核对来源记录；需要验证源码正文时按[维护指南](../CONTRIBUTING.md)恢复固定引用文件。两种检查会在结果中分别计数。

- `repository-snapshot.csv/json`：仓库身份、固定提交、抓取日期和元数据。
- `repos/<项目>/tree.txt`：该提交的完整文件目录。
- `repos/<项目>/files/`：采集的文档与按主题筛选的源码；不包含完整构建所需的所有文件。
- `repos/<项目>/manifest.json`：初次采集文件哈希；后补读取以相同固定提交为依据。
- `pages/*.txt` 与对应 JSON：成功采集的公开页面及来源信息；失败记录不能作证据。
- `review-core*.txt`：阅读辅助摘录，不是全文审计或运行测试。
- `review-log.json`：自动摘录脚本的运行记录；其中旧字段名含 reviewed 不应解释为逐行人工检查。
- `citations.csv/json`：正文使用的固定源码与页面引用。
- `source-manifest.json`：引用文件的固定提交、路径、采集时间、大小与 SHA-256；全文缓存不随 Git 分发。
- `external-references.csv`：正文全部外部链接。
- `catalog.json`：51 个主要编号工具的分类；维护观察档案 H01—H04 另列正文。
- `profile-coverage.json`：55 份统一档案的篇幅记录。
- `qa/report-structure-check.json`：栏目、图表、步骤、代码块、链接、导航和 SVG 静态检查。
- `delivery-summary.json`：当前交付内容和验证边界。

脚本读取公开 GitHub 与官方页面，未执行第三方仓库代码。`collect_repos.py` 按固定提交建立目录和文件快照；`collect_pages.py` 保存网页文本；`render_references.py` 生成固定链接；`build_inventory.py` 生成清单。重新执行网络采集会访问外部公开站点，且不会保证得到原报告相同时间的内容。

报告中的作者分析、产品状态和模型建议应连同日期阅读。源码文件存在，只证明实现路径存在，不证明商业发布版默认启用或已经过本报告实测。

## 编排与验证

报告编排使用 `build_profiles.py`、`profile_expansions*.py`、`profile_deepdives.py` 与 `profile_models.py`。这些文件将原有证据材料整理为统一档案，并添加作者分析、操作方案和任务示例。`integrate_report.py` 组织跨工具比较章节；`build_inventory.py`、`render_references.py`、`build_references.py` 分别维护目录和来源。`build_figures.py` 绘制通用概念图，工具图由档案生成器及 `profile_diagrams.py` 绘制；`build_report.mjs` 生成自包含 HTML。

`editorial-baseline/` 保存改写前的材料作为可恢复来源，其中的旧格式、链接与日期不代表当前报告。修改应落在相应编排源文件，再重新生成 Markdown，避免生成器覆盖手工编辑。该目录中的旧检查脚本只作留档，不属于当前默认验证流程。

完整阅读版的当前验证包括 Markdown、HTML、SVG、导航、来源及栏目覆盖的静态检查。此前本地 HTML 浏览器预览被 URL 策略拦截，本次没有通过其他浏览器路径绕过。旧浏览器截图和旧检查文件仅对应旧版本，不能作为当前页面的视觉验收。工具自身的功能与性能，也不能由报告文件检查来证明。

独立 SVG 的视觉抽查覆盖 A01、A15、B08、C02、C05、D02 六张图，分别代表执行循环、工作环境、检索、网关、代理宿主和工作流。缩略图由系统 Quick Look 从 SVG 直接生成，本机缓存保存在 `qa/diagrams/`，不入 Git；检查范围是图中文字、连线和边界，不包含 HTML 页面排版。具体文件与哈希见 `qa/diagram-visual-check.json`。

推荐在根目录运行 `npm ci --ignore-scripts`、`npm run build`、`npm run check`，详见[维护指南](../CONTRIBUTING.md)。构建读取 Git 中已有研究记录，不重新采集网络资料。需要逐步排查时，可按以下顺序运行：

```bash
python3 research/build_profiles.py
python3 research/integrate_report.py
python3 research/build_inventory.py
python3 research/render_references.py
python3 research/build_references.py
python3 research/build_figures.py
node research/build_report.mjs
python3 research/check_report.py
python3 research/check_report_structure.py
```
