# 易变事实刷新记录（2026-10-15）

本轮只核对会随时间变化的事实：模型型号与别名、API 价格、套餐规则、仓库维护状态和近期产品公告。工具架构、源码分析和固定提交快照沿用原记录，没有重新阅读源码。

## 做法

1. 从正文、档案生成器和旧稿中列出含具体型号、价格、日期和维护判断的位置，按“海外模型与多模型工具”“国内模型”“维护状态与产品公告”分成三张核对卡，交给工人逐条查官方页面，交回“仍成立／需改／查不到”的结论表。
2. 主控抽查关键结论，再用 `research/archive_sources.py` 归档本轮依据的 88 个官方页面。URL、读取时间和内容哈希写入 [`fact-refresh-sources.json`](fact-refresh-sources.json)；页面正文缓存在被忽略的 `research/pages/`，不入库。
3. 用 `research/refresh_repo_status.py` 通过 GitHub API 读取 42 个仓库的星数、最近推送、归档状态和最新 Release，写入 [`repository-status.json`](repository-status.json)。它不改变 `repository-snapshot.json` 中的固定提交。
4. 把核实结果写入 [`volatile-facts.json`](volatile-facts.json)。正文与档案不再逐处写死具体型号，改用占位符：`{{m:角色}}` 表示某个角色的当前型号，`{{table:表名}}` 插入带核实日期和来源的集中表，`{{date:facts}}` 插入核实日期。`resolve_volatile.py` 在生成时替换，遇到未知角色、未用条目或残留占位符就报错。

集中表共五张：模型家族（第 06 章 6.2）、Step API 价格与 Step Plan 套餐（6.5）、维护状态与近期产品变动（第 02 章 2.3）。场景表和工具档案的模型路线只引用角色名，下一轮刷新通常只需改 `volatile-facts.json`。

## 证据边界

- 所有结论来自官方文档、公告、模型仓库和 GitHub API 的公开信息，属于“文档声称支持”或“仓库元数据”层级，没有登录账户确认实际可选型号，也没有运行任何模型或 Harness。
- 第三方工具（Cline、Kilo、Kiro、OpenCode 等）是否已列出最新型号，以其各自目录为准。Cline 文档仍推荐 Claude Sonnet 4.6，因此档案只写“目录内当前的 Claude Sonnet／GPT 日常档”，不声称已适配 5.5。
- Qoder CLI 的型号列表本轮未核对，档案改写为“原采集时”。
- `stepfun-证据核对.md` 与 `公开前核查.md` 保留各自日期的原结论，作为历史记录阅读。
