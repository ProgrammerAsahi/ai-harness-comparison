## 先记住的几个判断

选型不能只看能接多少模型。真正有影响的是：工具是否适配模型，任务状态怎样保存，谁管理运行环境，以及结果是否方便验证。换了一个界面，也未必换了代理核心；Zed、Cherry、Warp 等产品已经能承载其他代理。

维护状态也需要重新核对。Continue 当前明确不再积极维护；Roo Code 已关闭并归档；Kimi、Pi、Copilot 的旧仓库状态又涉及迁移，不能一概判断停更。DeepSeek Harness 虽有很高关注度，仍需保留开发者预览的成熟度判断。

普通用户最好从一套原生或正式支持的组合开始，建立成功基线，再按实际瓶颈增加模型、检索、子代理或远程环境。没有必要先装完整个清单。

## 研究范围说明

这份报告进行了广泛资料采集和核心路径重点阅读，**没有逐行读完全部项目，也没有对所有模型组合做统一运行测试**。闭源产品按官方公开资料分析；场景推荐区分原生支持与选型推断，不提供伪造的性能排名。详细边界见第八章。
