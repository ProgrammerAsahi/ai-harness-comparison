# 03D｜相邻路线与维护观察：不要把旧印象当作当前产品

有些工具很重要，却不适合直接与一个桌面编码代理比较；另一些曾经流行，现在的维护状态需要重新判断。本章保留它们的研究价值，同时说明为什么不把它们全部作为新用户的默认推荐。

## D01 Dify：把模型能力做成可复用的业务应用

**理念与结构。** Dify 更接近 AI 应用与流程平台。用户组织输入、知识检索、模型、工具、分支和输出，再将流程交给其他人使用。代码中，Workflow Entry 负责图运行状态、节点与事件，Agent Runner 则在需要自治的步骤中循环调用模型和工具。确定流程与代理循环可以同时存在。[README](https://github.com/langgenius/dify/blob/a068c47ea993ccc0f943131c274b7830b16de9f4/README.md)、[工作流入口](https://github.com/langgenius/dify/blob/a068c47ea993ccc0f943131c274b7830b16de9f4/api/core/workflow/workflow_entry.py)、[工具调用代理](https://github.com/langgenius/dify/blob/a068c47ea993ccc0f943131c274b7830b16de9f4/api/core/agent/fc_agent_runner.py)

它的好处是：业务逻辑不必每次依靠模型重新猜。例如客户问题先分类，再检索对应知识库，证据不足转人工。代价是需要设计和维护流程、变量、权限与失败分支。

**上手与模型。** 从一个简单问答或资料提取流程开始，固定输入和输出格式；模型使用平台当前支持的 GPT、Claude、Qwen、DeepSeek 等。简单分类与复杂判断可以分配不同档位，但必须对整个流程验收。适合客服知识、文档处理、企业内部 AI 应用；临时修一个代码 bug 通常不是最简路径。难度：基础中；生产化高。许可证、企业能力和云服务与自托管差异应单独核对。

## D02 n8n：让代理进入已有的业务自动化

**理念与结构。** n8n 的起点是连接应用与触发流程，AI Agent 是其中可配置的节点。当前 Tools Agent 执行器建立模型、记忆、批处理等上下文，再将工具执行交还工作流引擎并接续结果，同时记录执行次数、失败类型和记忆读写等追踪信息。[README](https://github.com/n8n-io/n8n/blob/8012f017bc80a35cef0c3012033e9089c9db8e03/README.md)、[Tools Agent V3](https://github.com/n8n-io/n8n/blob/8012f017bc80a35cef0c3012033e9089c9db8e03/packages/@n8n/nodes-langchain/nodes/agents/Agent/agents/ToolsAgent/V3/execute.ts)

这与终端代理最明显的差别在于“什么时候开始做事”：可以由表单、计划、Webhook 或应用事件触发；输入输出已经是业务数据。模型负责有不确定性的环节，外层流程负责顺序与交接。

**上手与模型。** 先做“读取数据→生成草稿→人工确认→保存”四步，再加自动触发。简单步骤试经济模型，复杂判断试更强模型；只有确认所用节点支持相应接口后才接入。适合每周报告、线索整理、工单分类、跨应用资料处理。难度：中；可靠生产流程高。官方称其为 fair-code，不应把可见源码直接解释成无条件的宽松开源许可。

## D03 mini-SWE-agent：研究代理时，一个短循环有时比复杂平台更有用

**理念。** mini-SWE-agent 强调小而可理解的执行核心，面向软件工程任务与评测。当前 v2 的 Agent 反复执行查询模型、执行动作、加入观察；它也有步数、成本、时间与格式错误终止条件，并保存运行轨迹。[README](https://github.com/SWE-agent/mini-swe-agent/blob/04d809ceab9df28f9adaed044884180159172930/README.md)、[核心实现](https://github.com/SWE-agent/mini-swe-agent/blob/04d809ceab9df28f9adaed044884180159172930/src/minisweagent/agents/default.py)

少量代码更容易理解实验中到底改变了什么。代价是完整产品通常还需要的用户管理、丰富 UI、长期个人记忆和业务连接器不属于这个核心目标。

**上手与模型。** 使用官方教程，在隔离环境中跑一个 issue，固定模型、提示、环境和预算，再改变单一变量。适合模型／Harness 对照实验、课程教学、自动修复研究。模型应选择评测任务能稳定调用的接口；不因为 README 宣称某项基准领先，就推断它适合所有日常交互。难度：研究者中；非开发者高。

## D04 SWE-agent：仍值得理解，但官方已把主力转向 mini

SWE-agent 对代理如何使用软件工程工具、怎样给模型设计可操作接口，有重要历史与研究价值。其执行器围绕模型、环境、工具、格式检查与重试推进任务。[核心实现](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/agents.py)

但当前 README 明确表示主要开发精力转向 mini-SWE-agent，并建议新用户优先采用后者。即使仓库近期有推送，也不能把它当成与 mini 同等优先的新路线。适合复现实验、读旧配置或维护已有项目；不列为本报告的新用户首选。[维护说明](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/README.md)

## D05 Oh My OpenAgent／OmO：叠加在执行核心之上的编排体系

**不要只套用旧名。** 当前仓库是 `oh-my-openagent`，文档已经覆盖 Pi 相关路线和新的编排配置，不能一直按早期 OpenCode 插件的固定角色表介绍它。[README](https://github.com/code-yeongyu/oh-my-openagent/blob/d862a09a0cce8a77b14168bd68d5a29087b18d79/README.md)

**理念与结构。** 当前编排文档区分规划、执行、依赖图和团队模式。主代理保持任务所有权，通过任务工具委派；工作者可以按类别选择模型，探索与资料代理拥有受限职责。计划文件、进度状态与证据材料服务于继续执行和验证。[编排说明](https://github.com/code-yeongyu/oh-my-openagent/blob/d862a09a0cce8a77b14168bd68d5a29087b18d79/docs/guide/orchestration.md)

这类系统的收益在于把经验性的提示、任务拆分和复查做成可复用流程。代价是增加一层依赖：模型、底层 Harness、插件与配置都可能影响结果。升级任何一层都应做回归任务。

**上手与模型。** 先让底层 Harness 独立工作，再安装当前官方推荐的 OmO 路线；对一个具有独立子任务的项目试用，而不必让每个小改动都走完整编排。模型选择遵循角色配置和当前匹配文档，主代理用更强模型、机械任务用经济型号是一种待验证策略。难度：高。适合有能力维护配置的开发者，不适合作为完全不懂环境管理者的第一套工具。

### Aider 为什么仍值得读

Aider 将项目地图、代码编辑与 Git 工作流联系得很紧。RepoMap 用有限预算表示仓库中的重要结构，编辑器根据模型适合的格式修改代码；Architect 路线还把提出方案与具体编辑分工。[项目地图实现](https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/repomap.py)、[编辑核心](https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/coders/base_coder.py)、[模型与使用说明](https://aider.chat/docs/llms.html)

它说明：优秀 Harness 不一定需要庞大团队和几十种工具，精确的上下文和编辑协议也能形成鲜明路线。已有用户可以继续根据实际稳定性判断；新用户则应先核实维护和当前模型适配，不能照抄旧文章中的型号与排名。

## 另外三种“看似停更，其实是迁移”

- **Pi**：使用当前 `earendil-works/pi`，不要只追旧仓库地址或旧安装包。
- **Kimi**：当前 `kimi-code` 与旧 `kimi-cli` 不应按同一套源码架构描述。
- **Copilot Chat**：旧仓库归档后，编辑器侧开发迁入 VS Code；这不等于产品终止。

这也是为什么本报告同时检查仓库元数据、README、当前文档与实际源码入口。单看星数，或者单看最后一次推送时间，都可能得出错误结论。
