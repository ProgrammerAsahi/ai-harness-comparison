# 06｜模型搭配与成本：选对组合，而不是背一张永久排名

模型目录变化很快。原有型号依据 **2026 年 9 月 22 日** 可读取的官方文档；**Step 家族于 9 月 23 日增补核验**。这些型号用于说明当前候选，不是永久有效的安装清单。产品界面、地区、账户和 Provider 都可能限制可用型号。

本报告没有购买各家 API 跑统一基准，因此推荐的准确含义是“依据公开适配和任务特征，值得优先试用”。厂商自报成绩只用于了解定位，不用于证明跨产品冠军。

## 6.1 三种搭配证据，强度不同

| 标记 | 依据 | 怎样理解 |
|---|---|---|
| 原生组合 | 模型厂商自己的 Harness，或明确的专门适配 | 通常是最容易建立可工作基线的起点 |
| 官方支持 | 产品文档明确列出 Provider／模型／协议 | 证明有支持路径，不证明每个任务质量相同 |
| 选型推断 | 根据任务、工具与上下文特征提出 | 必须以自己的任务验证，不能冒充实测结论 |

例如 Claude Code＋Claude、Codex＋GPT、Kimi Code＋Kimi 属于原生路线；OpenCode／Cline＋某个目录内模型属于官方支持路线；“用经济型号做摘要，用强型号判断架构”则是工作分配建议。

### 型号名为什么容易误导

`sonnet`、`opus`、`kimi-for-coding`、`deepseek-flash` 可能是别名。别名让用户自动获得新版本，但降低了实验可重复性。当前 Claude Code 文档甚至按 Provider 列出不同映射；DeepSeek 文档说明部分旧型号名称仍被接受，实际已路由到新模型。

因此在调试或比较时，应保存四项：**Harness 版本、Provider、实际模型 ID／版本、请求参数**。只写“用了 GPT”或“用了 Claude”几乎没有比较价值。[Claude 映射](https://code.claude.com/docs/en/model-config.md)、[DeepSeek 别名](https://api-docs.deepseek.com/quick_start/pricing/)

## 6.3 怎样判断模型适不适合某个 Harness

按这个顺序检查，比一次跑一个庞大任务更有效：

1. **基础输入输出。** 中文、代码、文件片段是否正常；需要图像时，实际请求有没有把图像发送给支持图像的模型。
2. **工具往返。** 能否正确调用一个只读工具，读取结果，再作下一步决定。
3. **编辑与验证。** 能否按该工具要求修改文件，并用正确命令验证。
4. **错误恢复。** 文件不存在、命令失败、工具参数不合法时，能否根据错误调整，而不是重复同一错误。
5. **历史与压缩。** 会话变长或恢复后，是否记得关键约束；工具调用与结果有没有失配。
6. **控制与成本。** 中断能否生效；子任务是否继续烧费；模型窗口、输出上限与 Harness 的估算是否一致。

某些模型需要保留推理状态、签名或特定响应字段。网关如果只转发文本，看起来仍能聊天，却可能破坏长任务。也有服务仅在协议表面兼容，实际不支持某些参数。遇到这种问题应先核对适配层，而不是立即认定模型“变笨”。

## 6.4 开放权重与本地模型：适合什么，不适合什么

本地模型的主要收益是数据路径控制、可定制与不依赖外部推理服务。它并不天然更便宜或更快，尤其是在硬件已经不足、任务又需要很多重试时。

| 已有官方模型卡的候选 | 可搭配的路线 | 本报告建议的初始任务 | 验证重点 |
|---|---|---|---|
| Qwen3-Coder-30B-A3B-Instruct | Qwen Code／OpenCode／Pi＋正确配置的本地服务 | 局部代码问答、小修复、可验收脚本 | 工具模板、上下文、格式和修改正确性 |
| Qwen3.5-27B | Open WebUI／AnythingLLM／Chatbox／Cherry＋本地服务 | 中文资料整理、短报告、检索后的问答 | 中文事实准确性、量化损失、检索质量与速度 |
| gpt-oss-20b | 支持对应格式的本地推理服务＋兼容 Harness | 结构化推理、短工具任务、对照实验 | 服务端格式与工具适配，中文任务另测 |
| 更大型开放模型 | 具备资源的组织推理平台 | 经过容量规划的团队任务 | 权重许可、显存、并发、上下文缓存和运维 |

来源：[Qwen Coder 模型卡](https://huggingface.co/Qwen/Qwen3-Coder-30B-A3B-Instruct/raw/main/README.md)、[Qwen3.5-27B](https://huggingface.co/Qwen/Qwen3.5-27B)、[gpt-oss 模型卡](https://huggingface.co/openai/gpt-oss-20b/raw/main/README.md)。这些是可检验的候选，不是本地模型完整排行榜，也不意味着它们是截至当日最新的所有开放模型。

**硬件的一个简单估算。** 如果有 300 亿参数，粗略按每参数 4 bit 保存，仅权重理论下限约为 15 GB。实际还要加上量化元数据、运行缓冲、上下文缓存等，不能由此推出“16 GB 电脑一定能流畅运行”。不同架构和推理引擎也会改变实际需求。

MoE 模型每步只激活一部分参数，主要影响计算量；不能仅按活跃参数估计全部权重占用。上下文越长、并发越多，也可能越吃内存。先用短上下文测实际资源，再逐步扩展。

**完全本地需要整条链都本地。** 回答模型、嵌入模型、文档解析、搜索、语音、工具与日志都可能是独立服务。尤其知识库工具即使用本地回答模型，也可能仍把文档发给云端嵌入接口。

## 6.5 成本要按“完成一项可接受的任务”来算

一个实用的成本拆解是：

> 总开销 ≈ 订阅与平台费用＋模型输入输出费用＋缓存相关费用＋工具调用费用＋执行环境费用＋人工检查和返工。

同样一次“帮我修 bug”，背后可能调用几十次模型；子代理、摘要、标题生成、检索和重试都可能增加消耗。并行让等待缩短，不会自动让所有分支只收一份费用。

| 表面上很便宜 | 可能遗漏的开销 |
|---|---|
| 模型 Token 单价低 | 失败重试、上下文重复传输、需要更长输出 |
| Harness 免费或源码开放 | 模型 API、机器、网关、连接器和维护时间 |
| 已有某家聊天订阅 | API 未必包含在订阅里；第三方接入资格也可能不同 |
| BYOK | 平台部分能力可能仍另外收费，辅助模型可能不走自己的 Key |
| 本地模型不要 API 费 | 硬件、能源、部署与速度损失 |
| 多代理完成得快 | 总调用量、重复调查与合并成本 |

Qoder 的 Repo Wiki 单独计费就是一个具体例子：主对话使用 BYOK，不代表产品里的所有模型能力都改走同一账户。Factory 文档又说明不同入口对 BYOK 的支持范围不同。因此应读到功能级别，不能只看产品首页的一个词。[Qoder](https://docs.qoder.com/qoder/custom-models.md)、[Factory](https://docs.factory.ai/model-independence/byok.md)

### 缓存与压缩也有取舍

模型服务可能对重复输入提供缓存优惠。稳定的项目规则与工具列表有利于复用；频繁修改系统提示、切模型或更换工具集合，可能降低命中。另一方面，为了缓存而保留大量无关历史，也可能让任务更难理解。

压缩通常需要额外模型调用，且可能丢信息。合理目标是保留足够准确的任务状态，而不是让 Token 指示器始终最低。某次压缩少花了一点钱，却导致代理重做整个调查，整体并不划算。

## 6.6 订阅、API 与网关：使用前把钱和数据的路径画清楚

| 接入方式 | 谁提供模型 | 谁向你计费 | 需要确认什么 |
|---|---|---|---|
| 产品内置订阅／额度 | 平台选择或转售的模型 | 产品平台 | 包含哪些入口、模型、上限和额外费用 |
| 官方 API Key | 模型厂商 | 模型厂商，可能另有平台费 | 模型权限、余额、地域和数据设置 |
| 第三方网关 | 网关路由到上游 | 网关，可能加价或另有规则 | 实际模型、日志、协议转换、失败处理 |
| 本地／内网服务 | 自己部署的模型 | 硬件与运维资源 | 模型格式、版本、许可、容量和出口 |

优先使用产品官方支持的认证方式。不要因为某个不明插件声称能共用订阅，就默认它受到模型厂商支持；也不要将账户凭据交给未经核实的中间服务。

## 6.7 一个简单的升级策略

先用中等档位完成普通任务；若失败，要求代理说明证据和卡点。只有确实需要更复杂推理、更长资料理解或更稳定工具使用时，才升级模型。机械批处理先用小样评估经济模型，达到标准后再放大。

对重要任务，可以让第二个模型或独立代理审查，但它必须查看原始材料与实际结果。只让另一个模型阅读第一份答案，容易变成互相认可，而不是独立验证。

模型升级是解决问题的一条路径；更好的输入、项目说明、工具、检索和验收，常常同样重要。

## 6.8 Step-5-Preview：模型规格、适配路线与真实使用成本

**核验日期：2026 年 9 月 23 日。** Step-5-Preview 是阶跃星辰面向软件工程、专业知识工作和多步代理任务的旗舰预览模型。Step Code 则是运行这些任务的外壳。二者可以原生配套，也可以分别选择其他搭配；不要把模型评测分数直接当作 Step Code 产品分数。

### 规格怎样读

| 项目 | 官方公开信息 | 对使用者意味着什么 |
|---|---|---|
| 模型 ID | `step-5-preview` | 配置时填写实际 ID；“Step 5”只是易读名称 |
| 架构 | 稀疏 MoE，约 600B 总参数、每 Token 激活 27B | 600B 是约六千亿；27B 是约二百七十亿。计算只动用部分参数，存储不能只按活跃部分算 |
| 上下文 | 1M Token；文档最大输入同列为 1M | 约一百万 Token，不能直接换算成固定汉字或页数；工具说明与历史也占空间 |
| 最大输出 | 64k Token | 长输入不等于可以无限输出；仍受请求参数与服务约束 |
| 输入与输出 | 文本、图像、视频输入；文本输出 | 可以理解视觉材料；生成图片、视频或操作设备需要另外的工具 |
| 推理深度 | low、medium、high | 简单提取可试 low，日常先 medium，复杂规划与排障再试 high |
| 工具与结构化数据 | 工具调用、流式返回、JSON Mode／JSON Schema、提示缓存 | 适合嵌入代理；具体外壳必须正确转发这些字段 |

架构和权重计划依据[官方发布页](https://www.stepfun.com/step-5-preview)；窗口、输入输出和功能依据[模型文档](https://platform.stepfun.ai/docs/en/guides/models/step-5-preview)；推理档位依据[推理接入指南](https://platform.stepfun.ai/docs/en/guides/developer/reasoning.md)。`max_tokens` 未显式限制时的默认行为，不应理解为取消模型列明的 64k 上限。

图像文档列出每次最多 60 张，支持 URL 或 Base64；视频支持 URL、Base64 或文件引用，具体格式、大小与建议时长见模型页。**这描述的是服务接口能力。** 当前 Step Code 原生消息与文件工具可确认文本和图像路径，不能仅因为模型支持视频，就宣称终端也能把任意视频直接原样送入。需要视频时，先验证所用客户端的上传／消息格式。[输入输出限制](https://platform.stepfun.ai/docs/en/guides/models/step-5-preview)、[Step Code 工具](https://platform.stepfun.ai/docs/en/step-code/reference/tools.md)

Claude Code 的指南标明其检查过的客户端版本，并专门说明怎样让窗口统计与自动压缩使用 1M 设置。这恰好说明：只把模型 ID 改成 `step-5-preview`，未必已经获得整个百万窗口。OpenCode、Hermes 等入口也应查看实际配置，而非只看模型宣传页。Step Code 若未取得服务返回的窗口元数据，源码采用的后备值是 256,000；成本元数据还有零值后备，界面显示零估算也不能当作免费凭证。[Claude Code 窗口配置](https://platform.stepfun.ai/docs/en/step-plan/integrations/claude-code.md)、[Step 模型元数据实现](https://github.com/stepfun-ai/Step-Code/blob/adcf37b0572ff568b3fbff759f52267690c98c32/packages/providers/src/step-provider/index.ts)

### 参数、渠道与一个最小接入示例

海外按量 API 的 OpenAI Chat Completions 基地址是 `https://api.stepfun.ai/v1`；海外 Step Plan 对应 `https://api.stepfun.ai/step_plan/v1`。Claude Code／Anthropic SDK 的 Step Plan 配置基地址则不带末尾 `/v1`，依照 Messages 指南填写。中国区使用对应 `.com` 服务和账户。**地址不仅影响连接，也决定走订阅额度还是标准 API 余额。** [平台入口](https://platform.stepfun.ai/)、[Step Plan 渠道说明](https://platform.stepfun.ai/docs/en/step-plan/overview.md)、[Messages 协议](https://platform.stepfun.ai/docs/en/api-reference/chat/messages-create.md)

下面只是文本请求的最小示例，需要自行安装 SDK、配置环境变量和开通对应账户；它不包含代理循环，也没有在本报告中实际付费运行：

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["STEP_API_KEY"],
    base_url="https://api.stepfun.ai/v1",  # 海外标准 API 渠道
)
reply = client.chat.completions.create(
    model="step-5-preview",
    messages=[{"role": "user", "content": "解释这段代码的输入、输出和边界条件：……"}],
    reasoning_effort="medium",
    max_tokens=4096,
)
print(reply.choices[0].message.content)
```

接入代理后，还要测试工具失败重试、多轮工具结果、图像和压缩后继续。协议中的推理字段与档位应按 Step 文档处理；其他模型使用的 `xhigh`、`max` 名称不能凭直觉套用。档位更高通常意味着更多思考开销，未必改善格式改写或简单提取。[推理参数](https://platform.stepfun.ai/docs/en/guides/developer/reasoning.md)、[Chat Completions](https://platform.stepfun.ai/docs/en/api-reference/chat/chat-completion-create)

### 性能证据、开放状态与推荐边界

官方发布页列出的结果包括 DeepSWE v1.1 的 67.7%、内部 StepCodeBench 的 49.0%（avg@4），以及 FrontierFinance 的 66.4%。发布页注明 DeepSWE 使用 SWE-agent；因此即使成绩可复现，也不能直接证明 Step Code 比其他 Harness 强。内部基准、重复尝试统计与不同推理档位，还会进一步限制横向比较。该页也承认更难、更长的编程任务仍有提升空间。[厂商评测及设置](https://www.stepfun.com/step-5-preview)

这些资料支持把它列为软件工程、带图表的专业材料和研究报告的试用候选；尚不支持本报告断言它在所有复杂重构、中文小说或金融任务上优于 GPT、Claude、Kimi 等模型。研究与财务材料仍要回到原始来源和可复算的数据，不以文字流畅度验收。

**开放状态须与 Step Code 的 MIT 源码分开。** 核验当日，官方发布页写明模型已提供产品与 API 服务，计划于 **2026 年 10 月 15 日**正式开放。报告没有据此认定官方完整权重与最终许可已经可获得，也不将第三方同名上传当作官方发布证明。[官方发布计划](https://www.stepfun.com/step-5-preview)

即使之后正式取得权重，600B 级模型也不属于普通笔记本候选。仅作容量估算：按 16 bit 保存全部参数，理论原始权重约 1.2 TB；即使理想化按 4 bit 计算也约 300 GB，尚未包含额外元数据、运行缓冲与上下文缓存。这个算式不是实际发行包大小或部署承诺。家庭离线任务仍优先考虑本章前面较小、已有官方权重与成熟部署路径的模型。

选择顺序可以很简单：先以 **Step Code＋Step-5-Preview** 建立原生基线；已有 OpenCode、Cline、Kilo 或 Hermes 的用户，可按官方指南在原工具中做对照。若任务是短摘要、重复提取或小修改，再比较 Step-3.7-Flash／3.5-Flash；若需求是小说文风、严格离线或组织治理，则按这些需求另行选型，不必因为旗舰新发布就迁移整套工作流。
