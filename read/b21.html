B21 Superset：在一个桌面工作区里并行调度多个第三方代理

简档：保留定位、总体结构和能力边界；上手命令、试用任务和模型路线不再随事实刷新维护，选型请参考第 05 章的场景表与第 06 章的集中表。

定位与设计理念

Superset 是一个桌面工作区，用来同时运行 Claude Code、Codex、OpenCode 等第三方命令行代理。它自己不带推理循环，而是给每个任务准备独立的 Git 工作树、终端和端口，再把各代理的状态、改动审阅、浏览器预览和 PR 流程集中到同一个界面。可以把它理解成“外壳的外壳”：代理本身已经是模型的外壳，Superset 在多个代理外面再加一层调度与审阅。README

并行使用代理时，难点往往不在单个代理会不会写代码，而在几个代理同时工作时，分支会不会冲突、谁在等人回复、哪份结果已经可以审阅。Superset 把这些协调工作做成工作台。代价是它能管到多深，取决于每个代理开放了多少接口：状态提示、会话恢复和用量统计只对部分代理完整可用，自定义代理只得到工作区、工作树和终端。

下图结合所引源码与文档，画出本工具的主要责任分工；为便于理解，省略次要模块与错误分支。

官方文档把它的用法概括为“在工作区里委派，通过分支和 PR 集成”。宿主服务负责工作区的创建与删除、终端、文件监视和 Git 操作，桌面应用负责启动宿主服务并提供本机凭据；宿主服务也可以跑在另一台机器上，由手机或其他电脑连接。为了显示“工作中、等待输入、已完成”，Superset 会包装代理的启动命令，并在代理配置里安装生命周期钩子；模型请求由各代理直接发给用户自己的订阅或 API Key，Superset 不做中转。概念说明、宿主服务架构、代理支持表

仓库根目录的许可证是 Elastic License 2.0（ELv2）：源码公开，可以使用和修改，但不得把它作为托管服务提供给第三方，因此不属于 OSI 认可的开源许可，GitHub 元数据也只显示为 NOASSERTION。桌面端以 macOS 为主，Linux 版标为实验性质，暂无 Windows 版；远程访问、自动化和手机端需要付费的 Pro 档。许可证、常见问题

工作树只把各任务的工作文件分开。README 明确说明它不隔离进程，也不能防止合并冲突；几个代理改同一模块时，冲突仍会在合并阶段出现。状态钩子写进的是代理自己的配置文件，只在 Superset 的终端里生效，停用时可在设置中逐个关闭。状态检测 做法相近的开源项目有 Orchestrator.inc：同样给每个 worker 准备独立分支和工作树，另用本地守护进程跟踪代理会话、PR、CI 和审阅状态，汇总到看板上；它采用 Apache-2.0 许可，提供 macOS、Windows 和 Linux 桌面端。与 Oh My OpenAgent 这类在单个执行核心上叠加编排的做法相比，Superset 管理的是几个彼此独立的外部代理进程。

能力、状态与边界

观察项 实际机制／公开能力 对使用者意味着什么
自身定位 不自带推理循环，启动用户选择的命令行代理 代理能力、模型与计费仍由各代理决定
任务隔离 每个任务一个工作树、分支、终端与端口 只隔离文件，不隔离进程，也不防止合并冲突
状态与恢复 包装启动命令，并在代理配置中安装生命周期钩子 状态、恢复与用量统计按代理逐项支持，自定义代理只有基础功能
模型流量 代理直接连接用户自己的订阅或 API Key，不经 Superset 中转 额度与账单在各模型服务处分别查看
审阅与集成 改动查看、浏览器预览，把 PR 行级意见回送给代理 审阅仍需人来做，合并前运行项目测试
许可与平台 ELv2 源码可得；macOS 为主，Linux 实验，暂无 Windows 不得作为托管服务提供；远程访问等功能属付费档
