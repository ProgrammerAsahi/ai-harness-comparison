B20 Google Jules：把仓库任务交给独立云端工作机

简档：保留定位、总体结构和能力边界；上手命令、试用任务和模型路线不再随事实刷新维护，选型请参考第 05 章的场景表与第 06 章的集中表。

定位与设计理念

Jules 是异步编码代理：连接 GitHub，选择仓库和分支，在云端虚拟机中克隆代码、安装依赖、修改并验证。它与 Gemini CLI 的主要差别是环境和任务生命周期由服务管理。官方各页对它的成熟度说法不一：入门页写的是“实验性编码代理”，常见问题页写的是公开测试版（Public Beta），2025-08-06 的更新记录又宣布已结束测试；REST API 仍是 v1alpha 预览版本。选型时按尚在演进的产品对待。入门、常见问题、2025-08-06 更新记录、API 参考

Jules 把代码任务放到独立云端工作机上，让用户先交代需求，再回来查看计划与产物。与本机即时交互相比，它更依赖完整任务说明和可重复环境；优势是用户不必一直占用自己的终端。成熟度标注不一致、接口仍是预览版，也意味着使用者应保留对功能变化、可用性和结果质量的观察。

工作原理与架构图

下图依据官方公开接口整理，表示责任分工，不代表已审计闭源内部实现。

API 将源码来源、会话与活动分为不同对象，便于调用方持续跟踪任务状态与产物。云端环境要从仓库重新建立工作条件，本机正在运行的服务、未提交文件和个人环境变量不会自动出现。CLI 是服务入口，并不意味着同样的执行引擎被搬回本机。

能力、状态与边界

观察项 实际机制／公开能力 对使用者意味着什么
任务方式 异步云端编码 适合独立 issue 与批量维护
环境 独立虚拟机准备仓库与依赖 提供可重复安装和测试步骤
API 对象 v1alpha 版 REST API 中的 Source、Session、Activity 跟踪状态与产物，不能只看完成通知；预览版接口可能变化
项目规则 仓库说明及 AGENTS.md 等材料 未记录背景要补入任务或仓库
模型 原生模型路由 公开材料不支持任意 BYOK 的普遍承诺
成熟度 入门页称实验性，常见问题页称 Public Beta，2025-08-06 更新记录称已结束测试 说法不一致时按试点对待，保持小范围试点与正常人工审查
