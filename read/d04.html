D04 SWE-agent：仍值得理解，但官方已把主力转向 mini

定位与设计理念

SWE-agent 对代理如何使用软件工程工具、怎样给模型设计可操作接口，有重要历史与研究价值。其执行器围绕模型、环境、工具、格式检查与重试推进任务。核心实现

SWE-agent 的研究价值在于把软件工程环境与模型可操作接口结合起来。工具怎样呈现文件、错误怎样反馈、动作格式怎样检查，都可能改变完成率。当前维护重点已转向 mini，因此应把它作为复现实验与理解历史设计的重要材料，而不是无条件推荐新用户投入的活跃产品。

但当前 README 明确表示主要开发精力转向 mini-SWE-agent，并建议新用户优先采用后者。即使仓库近期有推送，也不能把它当成与 mini 同等优先的新路线。适合复现实验、读旧配置或维护已有项目；不列为本报告的新用户首选。维护说明

工具接口是一种提供给模型的工作方式：怎样看文件、怎样定位内容、怎样修改和验证，都影响模型下一步判断。格式检查与重试帮助处理不合法输出，却不能保证合法动作本身正确。复现实验时必须保留原工具和环境配置；只保留模型名字，通常不足以解释论文或排行榜中的结果。

深入一层：模型行动接口、环境观察与轨迹处理

SWE-agent 将模型和开发环境之间的交互界面作为研究对象：模型能看到哪些操作、输出怎样整理、错误怎样回到下一轮，都会影响问题解决能力。Agent 类组织运行、历史与轨迹，工具及环境则执行实际动作。因此“模型相同”并不足以保证与另一 Harness 的实验条件相同。

模块／交接点 怎样工作 状态与边界
行动接口 提示、动作格式和工具构成模型的操作面板 接口难用会增加格式失败与无效步骤。
观察处理 把环境返回内容送回后续决策 输出过长或缺失关键信息会改变任务难度。
轨迹证据 保留动作序列及终止原因 成功率之外还应报告环境和预算条件。

沿着一次任务看数据怎样走。 例如修复一个已知 issue：先确认失败测试，代理在环境中逐步调查和编辑；评测端再检查最终补丁。分析失败时沿轨迹找到第一次错误假设，而不是只读最后一段总结。

与相近工具的实质差别。 与 mini-SWE-agent 相比，更丰富的接口与处理提供研究控制点，也增加实验配置复杂度；与日常 IDE 产品相比，重点是可分析、可复现的软件工程任务执行。

能力、状态与边界

观察项 实际机制／公开能力 对使用者意味着什么
研究目的 软件工程代理与工具接口设计 适合理解模型如何操作环境
执行 模型、工具、格式检查与重试 格式合法与任务成功是两个指标
配置 任务、环境与模型共同定义实验 固定依赖和提示才能复现
轨迹 保存过程供分析 检查真实补丁和测试，不只看最终文本
维护 官方主力转向 mini-SWE-agent 近期推送不代表同等产品投入
使用建议 既有部署与历史实验仍可研究 新项目优先评估 mini 等更活跃路线

把机制放进实际工作。

工具接口不仅是功能集合，也影响模型怎样思考和行动。文件展示方式、错误提示和编辑格式都会改变后续选择；复现实验若更换这些条件，即使模型相同，也不再是原来的组合。研究旧结果时应把工具配置与提示当作实验的一部分保存。

格式重试能帮助纠正不合法动作，却不能证明合法动作有意义。不断执行同样的错误调查仍可能消耗预算，必须回到轨迹看模型是否利用了反馈。把格式失败、环境失败和推理失败分开，才能判断改进应该落在哪里。

维护转向 mini 后，旧项目仍可用于理解历史方法，但新工作应评估维护责任。迁移时先保留任务与验收，逐步替换执行器和工具，而不是一次改变全部条件。无法取得原模型或环境时，应明确称为新的对照研究，保留与历史实验的差异。

从安装到完成第一个任务

  1. 先明确是复现历史实验还是维护既有部署；新项目优先读官方维护说明，判断是否改用 mini。

  2. 复现时固定论文或实验所用提交、配置和任务数据，准备匹配的环境，不直接用最新依赖替换。

  3. 选择一个单任务验证工具、模型接口和轨迹保存，确认预算与停止条件符合实验设定。

  4. 独立检查补丁与测试，记录格式错误、环境错误和推理错误；不要把所有失败归结为模型水平。

  5. 需要迁移时，将任务、验收和环境先带到新执行器，再对照工具接口差异；不假定旧配置可原样加载。

检验的是复现和解释，而不是只跑出一个成功例子。模型版本不可用或环境变化时应说明不可比之处；不要用新环境得到的结果冒充原实验复现。

模型搭配、适用方向与取舍

选择路线 候选组合 怎样决定
复现实验 目标配置的精确模型版本 不可用时注明新条件，不冒充原实验复现。
方法对照 固定模型，只改一项 Harness 变量 同时固定环境、提示、任务数据和预算。
模型对照 固定 Harness，再更换模型 记录重复运行、终止原因与独立验收，不只选成功样例。

模型选择以目标实验原配置为优先；无法取得原型号时明确标为新的对照实验。已有用户可按稳定性继续维护，新用户更宜从 mini 入手。它仍适合研究工具接口设计，但长期产品化需要额外承担维护责任。
