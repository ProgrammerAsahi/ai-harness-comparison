B07 TRAE：从编程界面走向可交付的完整工作

简档：保留定位、总体结构和能力边界；上手命令、试用任务和模型路线不再随事实刷新维护，选型请参考第 05 章的场景表与第 06 章的集中表。

定位与设计理念

商业产品 TRAE 自 2026-10-09 起把原 TRAE IDE（TraeCode）与 TRAE Work 合并为同一个产品：一个入口、两种模式，Agent Mode 用于从需求推进到交付，可在多个项目间并行调度多个代理；IDE Mode 保留完整的 AI 开发环境，适合在单个项目里深入改代码和调试。桌面、Web、手机三端共用项目、任务和成果。GitHub 上的 trae-agent 研究代码与它不能互相替代，研究仓库的维护状态也不能证明商业产品当前活跃程度，因此研究仓库另列观察项。合并说明

新 TRAE 的 Agent Mode（承接原 TRAE Work，即更早的 TRAE SOLO）强调从需求走到成品。编程之外，资料、数据和报告也可以作为任务对象，用户无需每一步都手动把聊天内容复制成文件。对于不想配置大量工具的人，这种工作台有吸引力；但托管产品的内部路由和运行时不完全公开，因此应通过具体成果检验，而不根据角色名推断内部架构。

工作原理与架构图

下图依据官方公开接口整理，表示责任分工，不代表已审计闭源内部实现。

合并之前，SOLO 在 2026 年 3 月以邀请制测试推出独立桌面和 Web 体验，5 月 6 日取消邀请码并上线手机端，6 月更名为 TRAE Work，分 Work Mode（调研、写作、数据分析）与 Code Mode（应用开发）；专业开发者则使用 TRAE IDE。新 TRAE 把这两条线收进同一个入口，Agent Mode 还支持多目录的本地任务和经 SSH 连接的远程开发环境，Automation、插件与技能的 Marketplace、集中管理产物的 My Artifacts 也并入同一套工作流。其方向是减少“模型回答完，用户再手工整理成品”的断层。但闭源运行时的调度、压缩和内部模型路由无法从公开网页完整还原；合并说明是前端渲染页面，正文取自随页面返回的内嵌数据。官方产品页、TRAE Work 发布说明、取消邀请码与手机端、早期 SOLO 测试公告

从用户可见流程看，输入不仅是一句提问，还包括项目、附件和输出格式；代理将工作分阶段推进，并把结果放回可查看的产物。这个结构适合“先收材料、再分析、再制作”的任务。需要分别检查各阶段：读到资料不等于事实正确，生成文件不等于排版可用，原型跑起来也不等于后端、权限和部署已经完成。

能力、状态与边界

观察项 实际机制／公开能力 对使用者意味着什么
产品身份 2026-10-09 起原 TRAE IDE 与 TRAE Work 合并为一个 TRAE，与研究仓库 trae-agent 分开 研究仓库状态不能代表商业产品维护；旧教程里的两个产品名需要对应到新模式
任务范围 Agent Mode 从需求推进到交付、可并行调度多个代理，支持多目录本地任务与 SSH 远程环境；IDE Mode 用于单个项目内的深入开发 按具体模式确认可交付文件与工具
地区差异 国内／国际及不同版本 模型目录、额度和服务可用性分别核验
成品流程 任务执行与产物呈现结合 需检查中间依据和最终文件，不只看摘要
模型 产品可选型号或内置路由 不假定每个版本都有自由 BYOK
透明程度 商业内部实现未完整公开 以公开接口和实用验收为证据边界
