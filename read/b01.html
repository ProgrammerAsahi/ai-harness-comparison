B01 Cursor：把编辑器里的即时上下文变成代理的工作起点

简档：保留定位、总体结构和能力边界；上手命令、试用任务和模型路线不再随事实刷新维护，选型请参考第 05 章的场景表与第 06 章的集中表。

定位与设计理念

Cursor 的优势是人仍在编辑器中工作，代理却能持续获得文件、选择区域、诊断与项目线索，并直接提出和执行修改。Agent 的工具、指令与模型适配共同构成执行体验；代码索引是帮助它找到相关材料的一条路径，不意味着每轮把整个仓库全部塞给模型。Agent 文档

Cursor 把代理放在开发者已经工作的编辑器里。当前文件、选区、诊断和项目搜索共同构成任务起点，用户可以边看代码边修正代理方向。这降低了交接成本，尤其适合需求逐步成形的界面开发。与一次性把 issue 交给远程工作者不同，这条路线的收益很大一部分来自人与代理之间快速来回，而非无人参与的最长运行时间。产品归属也有变化：2026-08-14，Cursor 在官方博客宣布已被 SpaceX 收购，完成了 4 月开始的收购程序。新购买的套餐改为 The X Subscription 的一部分，与 Grok 共用每周用量；旧套餐照常可用，是否切换由用户决定，见订阅说明。

工作原理与架构图

下图依据官方公开接口整理，表示责任分工，不代表已审计闭源内部实现。

当前产品还扩展了子代理、项目协调和云端工作。应把本地交互式编辑、后台任务和自动化分别评估：它们接触的环境、凭据和可运行时长可能不同。子代理能够减少主对话被探索细节占满的问题，但最终仍要有人检查集成结果。子代理

代码索引相当于项目的查找目录：它先帮助找相关材料，再由模型根据本轮任务阅读和行动。索引能减少盲目搜索，但被排除的文件、陈旧内容和隐含业务规则仍可能遗漏。子代理可以承接调查，主代理再整合结果。云端 Agent 则多出独立环境、仓库授权和结果取回过程，所以本地 Agent 跑通并不能证明云端任务也已配置好。

能力、状态与边界

观察项 实际机制／公开能力 对使用者意味着什么
即时上下文 文件、选区、诊断与项目线索 给出具体入口通常比泛泛要求重写项目有效
项目索引 检索相关代码后进入模型上下文 用已知答案抽查检索，不把索引视为整仓理解
交互方式 补全、局部编辑与多步 Agent 按任务尺度选择，减少不必要的长循环
分工 子代理与项目协调等能力 独立探索后仍需检查接口和文件冲突
云端 独立任务环境与自动化 重新配置依赖、秘密信息与仓库权限
模型 自有 Composer 2.5 与 Grok 4.x，另可选第三方模型；Plus 档没有 Auto 和第三方模型，Premium 及以上按 API 标价从预付额度扣费 Balance／Intelligence 自动路由仅限 Teams／Enterprise；比较时记录实际套餐、路由和账单规则
