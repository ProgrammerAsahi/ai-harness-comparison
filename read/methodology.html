08｜研究方法、证据与参考资料

8.1 本报告实际做了什么

本报告先做候选发现和维护筛选，再采集公开仓库目录、文档与核心源文件，并围绕以下路径检查实现：

用户任务进入 → 组织上下文 → 请求模型 → 分派工具 → 权限与执行 → 保存结果 → 压缩／记忆／子代理 → 恢复、结束与验证。

本报告现形成 46 个核心工具／产品家族档案、5 个相邻或转移重点项目、4 个维护观察条目和 40 个场景建议。42 个仓库快照包含支持性仓库，例如 OpenHands SDK、VS Code 和 Qwen 文档仓库，因此“仓库数”不是“独立产品数”。

所有工具按相同的七个维度编排，配有责任分工图、能力表、操作步骤与任务卡。可见源码和商业公开资料的证据深度不同，图示明确区分依据；文字长度不作为审计深度或产品质量的评分。

对“通读代码库和所有文档”的诚实说明： 本次没有完成几十个项目全部文件的逐行阅读，也没有完整审计每一项依赖；闭源商业运行时本来就不可全部取得。实际深度是：对收集仓库做文件目录普查，保存广泛文档与按主题筛选的源码，对核心执行路径、架构文档和关键边界进行重点阅读。不能把下载过、检索到或自动摘录过，写成已经逐行读完。

报告也没有对所有工具安装运行、购买全部模型套餐或开展统一性能基准。故“适合”“优先试用”属于有来源约束的选型分析，不能解释为实测速度、成功率或安全保证。

8.2 来源分成四种，不混为一种结论

来源类型 能支持的结论 不能单独支持的结论
固定提交的源码 某一版本包含什么执行路径、接口与约束 发布版必然默认启用，或该机制在所有场景都可靠
官方文档与更新说明 官方支持的入口、配置、模型和产品意图 独立性能优势或真实用户规模
仓库 API 元数据 当时的星数、归档标记、推送时间 活跃使用人数、维护质量、未来持续性
本报告分析 架构取舍、潜在适用性、试用方案 没有做过的实测结果

对冲突信息的处理原则是：当前明确维护声明优先于最后推送时间；当前仓库与文档优先于历史教程；功能按入口、版本与开关区分。厂商宣传中的成功率、速度提升、成本节省没有被本报告重新当成独立事实排名。

8.3 可复核材料放在哪里

路径 内容
repository-snapshot.csv 42 个仓库的规范地址、提交、抓取时间、星数、归档状态与目录规模
repository-snapshot.json 同一清单的机器可读形式
catalog.json 51 个主要编号档案的产品分类与章节映射；另有 H01—H04 四份维护观察档案
citations.csv 由正文引用解析出的固定源码和官方文档来源
external-references.csv 正文中全部外部链接的去重清单，包括手动添加的官方链接
research/repos/<项目>/metadata.json GitHub API 元数据原始快照
research/repos/<项目>/manifest.json 固定提交、采集文件和哈希清单
research/repos/<项目>/tree.txt 该提交下的完整文件路径目录
research/repos/<项目>/files/ 实际保存的文档与源码，不是完整可构建检出
research/pages/ 成功读取的官方页面文本与抓取元数据
profile-coverage.json 55 份档案的结构覆盖与篇幅记录
research/review-core*.txt 为阅读生成的带行号摘录；它们不是完整审计证明

采集脚本只读取公开数据，没有运行被调研仓库里的项目代码。源码通过固定提交归档获取；个别补充文件按同一提交读取。官方网页通常会变化，因此记录抓取日期与内容哈希，并在正文尽可能引用具体页面。

网页抓取并非全部成功。部分页面返回 403、跳转、空壳 HTML 或失效路径；这些失败没有被当作支持证据。部分动态文档通过联网阅读工具核对，正文仍指向原始官方 URL。引用存在不等于页面未来不会改变。

动态页面可能需要读取实际呈现内容；网页、公开源码与发行二进制也可能不同步。报告按证据分别判断，不将抓到网页、找到源码或绘出概念图当作实际运行验证。各来源保留自己的采集时间，本报告没有将所有项目伪装成同一天全面重验。

8.4 深度与证据边界

研究对象 本次实际检查的重点 仍然缺少什么
Codex、OpenCode、Pi、Gemini、Qwen、Kimi、MiMo、DSH、Step 等公开核心 循环、会话、工具分派、压缩、权限与子代理的代表路径 所有平台与所有配置的运行验证、完整依赖审计
Cline、Kilo、Goose、Crush、Vibe、Grok、OpenHands 当前产品结构与核心模块；入口和版本差异 全量插件、每个商业服务和部署组合
Hermes、OpenClaw、Agent Zero 持久状态、记忆、渠道／任务生命周期、委派 长时间稳定性、真实个人账户接入测试
Chatbox、Cherry、Open WebUI、LibreChat、LobeHub、AnythingLLM Agent 能力与会话／工具／知识工作台结构 全部发行版对应关系、多人生产部署压力与隔离测试
Cursor、Devin、Kiro、Junie、Amp、Factory 等商业产品 官方文档、模型与功能边界、公开接口 未公开内部实现、独立付费用户统计、统一实际任务测试
模型搭配 当前官方型号、原生适配与协议说明 所有组合的成功率、中文文风盲评、真实总成本

这张表的作用是让读者知道哪些判断已经有代码或文档支撑，哪些应该在采购或投入生产前补测。不同对象的公开程度不同，无法假装证据深度完全一样。

8.5 为什么不直接照搬排行榜

SWE-bench 类评测关注给定代码库中的问题修复；Terminal-Bench 关注终端任务。它们有价值，但任务、模型版本、预算、工具、运行环境、重试次数与评分方式都会影响结果。判断是否适合小说创作或公司项目时，还需使用对应任务验证。SWE-bench、Terminal-Bench

如果要公平比较 Harness，理想方法是固定模型和任务，再改变运行外壳；如果要比较完整产品，就允许各自使用原生配置，但同时记录总费用、人工介入与功能限制。两种实验分别回答模型比较与产品选型问题，结果按各自条件呈现。

8.6 适合继续追踪的变化

后续更新应优先核对：仓库迁移与维护声明、主要执行核心重构、默认权限变化、团队功能从实验到正式的状态、模型别名映射、订阅与 BYOK 范围、长任务恢复机制，以及数据与日志实际流向。

对本报告标记的预览与生态补充候选，优先补充任务复测，再依据新证据调整推荐。若希望将这份调研变成组织级选型，下一步应从第五章选两三个组合，执行第七章的真实任务评估。

8.7 完整参考索引

为避免正文被长网址占满，固定提交、源码文件与官方网页的完整索引另列在参考资料索引。正文关键事实附近也有直接链接。来源索引是可追溯入口，不表示其中每份文档的每一行都已阅读。

网页标题旁的标识用于识别工具，点击可查看官方来源。部分产品沿用厂商品牌或关联品牌，具体说明见标识来源记录。标识保留原有权利，不代表厂商背书。每份档案的下一层架构图及局部放大图均有相邻证据；它们是针对关键路径的解释，不代表完整内部审计。
