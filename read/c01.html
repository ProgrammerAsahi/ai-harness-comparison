C01 Hermes Agent：把一次任务的经验变成下一次可用的材料

定位与设计理念

Hermes 将长期使用放在中心：会话可以检索，经验可以写成记忆和 Skills，任务可以从 CLI、消息渠道或自动化入口到来。“会越用越懂你”在工程上主要意味着保存并重新使用材料，不是每聊一次就训练模型权重。README

Hermes 更关注长期使用而非单次回答。一次任务留下的经验、偏好与方法，可以在下一次被重新读取。其价值取决于保存的信息是否正确、是否能找回来以及是否及时修订。它适合有连续项目与重复工作的人；偶尔聊天的人未必需要承担多渠道和持续服务的配置成本。

工作原理与架构图

下图结合所引源码与文档，画出本工具的主要责任分工；为便于理解，省略次要模块与错误分支。

Python 会话循环把模型请求、上下文准备、工具分派和结果处理拆成多个部分；模型协议经适配后进入统一执行逻辑。记忆管理又通过独立 Provider 接口工作。在压缩前保存必要信息，是避免长任务丢失关键进展的一条路径。循环、记忆管理

委派工具为子任务建立独立代理，主代理通常只看见任务与摘要，而不是所有中间步骤。源码还为子任务处理模型覆盖、工作树、取消和预算。特别要注意，子代理可以有自己的运行预算，父任务上限不能直接当作整棵任务树的总成本上限。委派工具

长期信息不应都塞进同一段提示。偏好描述你一般怎样工作，项目事实描述某个项目目前是什么样，Skill 描述一套可复用的方法，当前进度则记录这一项任务做到了哪里。Hermes 的记忆 Provider 和会话循环为这些材料提供保存与使用路径，但内容治理仍然重要。子代理拥有自己的上下文与预算，主任务得到汇总，因此要明确哪些结论值得长期保存，不能把未经核对的探索猜测直接变成记忆。

深入一层：当前对话、持久记忆与委派的三种状态

Hermes 将单轮对话的请求、工具调度、重试与压缩放在 conversation loop 中，持久记忆则由专门模块管理。二者最容易被混淆：对话中出现过一件事，不代表它已经成为长期可用的记忆；记忆中保存了一个结论，也不代表它对今天的任务仍然正确。委派又是第三种状态，应带着明确输入返回结果。

模块／交接点 怎样工作 状态与边界
当前会话 保持正在进行的任务与观察 压缩改变输入组织，不能代替重要成果归档。
持久记忆 为后续任务保留可复用背景 需要核对适用范围、来源和过期信息。
委派 把一部分工作交给子任务 子结果应经过主任务核验再进入长期资料。

沿着一次任务看数据怎样走。 例如持续整理个人知识库：当前会话处理这批材料，委派只调查指定主题，最终确认的偏好或事实才作为长期背景。若把一次猜测长期记住，后续任务会反复沿用错误，因此验收应包含“写入了什么记忆”。

与相近工具的实质差别。 与以仓库为中心的 CLI 相比，Hermes 更突出跨任务持续性；与 OpenClaw 相比，长期记忆与常驻消息网关仍是不同架构维度。

本节细图与机制依据：conversation_loop.py、memory_manager.py、delegate_tool.py。箭头表示主要信息或控制交接，不表示所有分支必然并行；省略的模块不能视为不存在。

能力、状态与边界

观察项 实际机制／公开能力 对使用者意味着什么
长期材料 记忆、历史检索与 Skills 经验复用依赖正确保存和命中，不是训练权重
压缩 上下文处理与压缩前的信息保存 关键事实应有可读出处，便于恢复核对
委派 独立代理、可选模型及工作树 任务描述需包含交付格式和证据要求
预算 子任务可以拥有自己的上限 父任务预算不自动等于整棵任务树总额
入口 CLI、消息和自动化等路线 长期在线增加身份、服务与凭据管理
记忆治理 材料可积累，也需要修正 明确哪些是偏好、事实、临时判断与过期信息

把机制放进实际工作。

记忆至少有准确性、相关性和时效三个问题。保存的内容可能原本就错，也可能正确但与当前任务无关，还可能已经过期。长期使用应定期抽查重要事实与偏好，保留来源和修订方式。一次成功找回旧对话，只验证了检索的一部分。

Skill 应保存稳定的方法，例如核对报告数字的步骤；项目进度则记录特定任务现在做到哪里。把临时失败、未经确认的偏好或推测都写入长期方法，会让错误在以后反复出现。更合理的做法是完成任务并核对后，再提炼可复用经验。

子代理提供独立上下文，减少主任务被探索过程挤满，但也需要完整交接。研究者应返回来源、冲突和不确定项，而不只交一个结论。预算应合计主任务、所有委派、记忆处理与失败重试。消息渠道和定时任务启用后，还要检查身份、服务在线和重复动作，这些属于持续助理的完整成本。

从安装到完成第一个任务

  1. 先按官方指南只配置本地 CLI 与一个模型，用一份资料整理任务验证工具、输出和保存位置。

  2. 给代理明确项目材料与引用要求，让它生成报告；检查事实后再决定哪些经验适合写入长期记忆或 Skill。

  3. 开启新会话询问上次任务，检查它是否能找到正确资料并保留来源；故意更新一项事实，验证旧信息怎样被修正。

  4. 独立研究较多时再委派子任务，规定输入、输出和预算，汇总时检查证据冲突及总成本。

  5. 最后才接消息渠道和定时工作。验证触发者身份、任务运行环境与结果投递，并安排对记忆和失败任务的定期检查。

典型任务与验收方法

下面是一份可直接改写使用的试用任务，属于本报告设计的验收示例，并非已完成的运行测试。

每次根据新访谈补充同一份研究档案，保留来源和冲突观点。记住报告格式偏好，但不要把未证实的市场判断写成永久事实。

做两次相隔的任务，才能观察长期价值。检查第二次是否准确找回既有材料，是否知道哪些事实已改变，以及能否解释来源。记得很多却无法纠错，比少记一些且依据清楚更难维护。

模型搭配、适用方向与取舍

建议用可靠的 GPT／Claude 工具模型建立基线；中文任务与成本敏感场景比较当前适配的 Kimi、Qwen、DeepSeek。接本地模型时应检查真实上下文和工具调用能力，不能只看模型参数。适合持续研究助理、个人工作自动化、跨会话项目管理、从重复工作积累 Skills。难度：CLI 中；长期在线与多渠道运维高。

选择路线 候选组合 怎样决定
执行基线 已适配的可靠 GPT／Claude 工具模型 先完成文件、检索、计算和错误恢复，建立可信基线。
中文与成本 当前支持的 Kimi／Qwen／DeepSeek／Step 使用真实任务比较；记忆和工具能力来自运行时，不来自模型名字。
本地试验 正确服务的开放模型 先测短任务和多轮调用，复杂长任务另行验收。

适合持续研究、个人自动化和从重复工作积累方法。代价主要在记忆质量、多入口身份与长期运行。与编码 CLI 比较时看跨会话收益；与 OpenClaw 比较时，一个更突出经验与方法复用，另一个更突出渠道、设备与持续连接。
