D03 mini-SWE-agent：研究代理时，一个短循环有时比复杂平台更有用

定位与设计理念

mini-SWE-agent 强调小而可理解的执行核心，面向软件工程任务与评测。当前 v2 的 Agent 反复执行查询模型、执行动作、加入观察；它也有步数、成本、时间与格式错误终止条件，并保存运行轨迹。README、核心实现

mini-SWE-agent 把研究所需的关键循环保持得很短：问模型、执行动作、加入观察，再重复。少量核心逻辑让人更容易知道实验改变了什么，也更容易检查轨迹。它不以提供完整个人助理产品为目标；缺少某些界面或长期记忆，可能是研究可解释性与简洁性的取舍。

工作原理与架构图

下图结合所引源码与文档，画出本工具的主要责任分工；为便于理解，省略次要模块与错误分支。

少量代码更容易理解实验中到底改变了什么。代价是完整产品通常还需要的用户管理、丰富 UI、长期个人记忆和业务连接器不属于这个核心目标。

循环中的每次观察都进入后续模型输入，运行限制防止无限持续。轨迹让研究者看到模型什么时候走错、工具返回了什么，以及终止是完成还是预算耗尽。比较模型或工具时固定其他变量，才能解释结果：同一模型、不同提示属于提示实验；同时换模型、环境和预算，则难以说清哪一项带来提升。

深入一层：极简循环中每一步到底保存了什么

mini-SWE-agent 把模型查询、动作执行和观察回填保持在很短的核心路径内，方便研究者定位实验变量。消息历史记录模型看过什么，执行环境决定命令实际上做了什么，终止判断决定为何停止。这三件事一起才构成一条可解释轨迹。

模块／交接点 怎样工作 状态与边界
消息状态 问题、动作和观察连续累积 核对摘要保留了哪些信息，并保存原始材料供追溯。
执行环境 命令在指定环境运行并返回观察 依赖失败应与代码推理失败分别统计。
终止与评测 预算、格式和完成信号影响退出 正常退出也不能代替补丁验收。

沿着一次任务看数据怎样走。 例如比较两种工具提示：固定仓库、模型和预算，只改提示，保存每轮动作与输出，再用同一测试验证补丁。若同时换环境和模型，就无法把结果差异可靠地归给提示设计。

与相近工具的实质差别。 与 SWE-agent 较丰富的接口与轨迹处理相比，mini 路线强调少量核心代码；与产品型工具相比，它不会自动提供完整组织治理和个人助理体验。

能力、状态与边界

观察项 实际机制／公开能力 对使用者意味着什么
核心 查询、动作、观察的短循环 适合教学与控制变量实验
限制 步数、成本、时间和格式错误 终止原因应与成功率一起报告
环境 软件工程任务的实际执行环境 依赖和测试基线必须可重复
记录 保存运行轨迹 用于解释失败，不能代替独立验收
模型 依接口选择可稳定调用的型号 评测需固定版本与采样条件
产品边界 不以完整多用户工作台为重心 个人记忆、权限治理与连接器需另行设计

把机制放进实际工作。

短循环使实验变量更容易控制，但并不意味着环境可以忽略。相同模型和提示，在不同依赖、工具或测试版本中也可能得到不同结果。保留固定仓库状态与执行环境，是解释成功率的基础。

轨迹分析应找到第一个实质性偏差：没找到关键文件、生成错误动作、误解工具输出，还是在预算结束前没有验证。这样可以将改进落实到文件检索、动作生成、反馈理解或验证等具体环节。最后文本中的自评只是一条消息，独立检查才决定任务是否完成。

对照实验还要防止只挑成功案例。记录全部任务、终止原因、重试和预算；模型输出随机时观察多次结果，工具配置变化则一次只改一项。它适合把代理机制讲清楚，但研究结果推广到日常产品时，仍需考虑界面、权限、历史和人工协作这些额外层次。

从安装到完成第一个任务

  1. 按官方教程安装并选择受控环境，准备一个已知 issue 和固定仓库提交；记录原有测试结果。

  2. 配置模型、提示与预算，先运行单个任务，确认轨迹和产物被保存到可检查位置。

  3. 查看失败或完成的真正原因，核对补丁是否解决问题，而不只读取模型最后一条消息。

  4. 只改变一个实验变量，再重复相同条件。若模型输出有随机性，用多次任务或重复运行观察波动。

  5. 报告成功、失败类型、预算和环境条件，并保存配置；日常开发选型还需加入自己的任务与人工协作条件进行试用。

模型搭配、适用方向与取舍

使用官方教程，在隔离环境中跑一个 issue，固定模型、提示、环境和预算，再改变单一变量。适合模型／Harness 对照实验、课程教学、自动修复研究。模型应选择评测任务能稳定调用的接口；不因为 README 宣称某项基准领先，就推断它适合所有日常交互。难度：研究者中；非开发者高。

选择路线 候选组合 怎样决定
复现实验 目标配置的精确模型版本 不可用时注明新条件，不冒充原实验复现。
方法对照 固定模型，只改一项 Harness 变量 同时固定环境、提示、任务数据和预算。
模型对照 固定 Harness，再更换模型 记录重复运行、终止原因与独立验收，不只选成功样例。

适合代理课程、自动修复研究和模型／Harness 对照实验。日常用户若需要完整审批、团队协作和长期个人资料管理，通常还要额外搭建。简洁有助于解释结果，不代表它天然在所有任务上更快或更准确。
