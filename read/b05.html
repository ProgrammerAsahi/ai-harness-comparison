B05 JetBrains Junie：让代理使用 IDE 已经理解的代码结构

简档：保留定位、总体结构和能力边界；上手命令、试用任务和模型路线不再随事实刷新维护，选型请参考第 05 章的场景表与第 06 章的集中表。

定位与设计理念

Junie 的差异化在 JetBrains IDE 的代码理解能力：项目、符号、导航、诊断和运行配置已经存在，代理可以借此工作，而不必完全依赖文本搜索。当前产品还包含 CLI、CI 和远程监控等入口，已经不是只能在 IDE 中调用单一模型的小功能。官方产品页

Junie 现在有几个入口：JetBrains IDE 中的插件（可以在 AI Assistant 的 AI Chat 里选用，也可以单独打开工具窗口），独立运行的 Junie CLI，以及在 CI 运行器上执行的 GitHub Action 和 GitLab CI/CD。JetBrains Air 是另一层：它是 IDE 里同时管理多个代理会话的工具窗口，本身不提供模型，也不预装代理；Junie 是它开箱支持的代理之一，与 Codex、GitHub Copilot、Claude Agent 等并列。费用上，Junie Lite 是随 JetBrains 账户提供的免费模型档，只在 Air 和 Junie CLI 中可用，AI Assistant 里没有；文档称它不是试用，背后模型目前是 Qwen 3.6 27B，以后可能更换，发布博客的脚注却写明这项优惠有效至 2026-12-31，两种说法并存，长期使用前以届时的官方条款为准。日常机械改动交给 Lite，难题留给付费额度或自带 Key 的前沿模型，是官方给出的分工。Air 抢先体验、Junie Lite 文档、Junie Lite 发布

工作原理与架构图

下图依据官方公开接口整理，表示责任分工，不代表已审计闭源内部实现。

计划阶段可以形成可编辑、可提交的需求／设计／交付材料；实施阶段可用另一档模型。其价值是让“为什么这样改”保存在项目中，同时使用 IDE 的已有工具验证结果。需要注意，宣传中的基准成绩属于厂商材料，本报告没有据此宣布它普遍优于其他代理。

Junie 的优势来自 IDE 的项目理解，而这份理解只在连上 IDE 时才有。Junie CLI 自己就能读写文件、运行命令；同一项目在 JetBrains IDE 中打开并装有 Junie 插件时，CLI 会自动发现并连接它，借用符号感知的搜索、代码检查、测试发现与运行、重构等能力。没有连上时，CLI 仍能工作，只是这些依赖 IDE 的能力不可用。较大的任务通常先进入计划模式：代理只做只读探索，产出包括需求、技术设计、测试和交付步骤的计划，用户确认后才开始修改，也可以只保存计划、不实施。产品页说计划存放在项目的 .junie/plans 目录中，可以编辑和提交。执行中可以插话改方向；没有开启 brave 模式时，运行命令、调用 MCP 工具、读取项目外文件等敏感动作会先请用户确认，常用动作可写进允许列表。IDE 集成、计划模式、允许列表

状态分在几处。项目规则读自仓库里的 AGENTS.md 或 .junie/AGENTS.md，个人的全局规则放在用户目录的 .junie/AGENTS.md，两者冲突时以项目规则为准；计划文件跟着仓库走；会话由本机的 CLI 或 IDE 进程运行，Air 另有云端运行，目前只面向有 AI 席位的组织。远程模式只是通过 Junie 网页服务，把仍在本机运行的会话同步到浏览器，电脑睡眠时会话也随之暂停；它需要 JetBrains 账户或 Junie API Key，只有自带 Key 不够。GitHub Action 完全在用户自己的 GitHub 运行器上执行，结果以评论或 PR 交回。模型方面，CLI 可以直接使用 OpenAI、Anthropic、Google、xAI 等服务商的 Key，费用由服务商计；同一模型两边都可用时，优先走自带 Key。Junie Local 则在本机运行本地模型，通过 OpenAI 兼容接口接入 CLI，目前只支持较新的 Apple Silicon Mac 和带 NVIDIA RTX 显卡的 Windows 电脑。规则与记忆、远程模式、GitHub Action、自带 Key、Junie Local

与同样以 IDE 为宿主的 Augment（B08）相比，Junie 借用的是 IDE 现成的语义索引和运行配置，Augment 则以自己建立的 Context Engine 检索为中心；与只在终端里工作的代理相比，Junie CLI 离开 IDE 就少了这项优势。

能力、状态与边界

观察项 实际机制／公开能力 对使用者意味着什么
入口 IDE 插件、Junie CLI、GitHub Action 与 GitLab CI/CD；Air 是管理多个代理的宿主 逐个入口确认可用的代码理解能力与计费方式
项目理解 CLI 连上同一项目的 IDE 插件后，才能用符号、检查与测试能力 先确认项目索引、SDK 与运行配置正确
计划 只读探索后产出需求、设计、测试与交付步骤，存放在 .junie/plans 计划要具体到接口和兼容要求，确认后再实施
状态归属 规则在 AGENTS.md，计划在仓库，会话在本机进程；远程模式只做同步 电脑睡眠会中断远程会话；CI 入口在运行器上执行
模型 JetBrains AI 额度、免费 Lite 档、自带 Key 与 Junie Local Lite 背后的模型可能更换，部署路线和型号以账户与版本为准
权限 敏感动作默认先确认，可写入允许列表；brave 模式不再询问 试用时保留确认，稳定后再按动作类型放宽
