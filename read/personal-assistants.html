03C｜个人助理与知识工作台：围绕长期信息和日常工作组织代理

这类工具的起点通常不是一个 Git 仓库，而是人、资料、对话和外部应用。它们越来越多地加入代码执行、子代理、浏览器和定时任务，因此不能沿用“都是聊天皮肤”的旧判断。

这里更需要问三个问题：长期记忆存在哪里？谁能触发任务？代理操作的是哪个人的账户和工作空间？ 同样一次工具调用，放在一个临时编程会话中，与放在持续在线的聊天机器人里，管理难度很不一样。

档案读法： 每个工具均按七个相同维度展开。架构图用于理解责任分工；上手步骤与任务卡用于实际试用。代码块是命令或操作示例，不表示本报告已经运行全部工具。

C01 Hermes Agent：把一次任务的经验变成下一次可用的材料

Hermes 将长期使用放在中心：会话可以检索，经验可以写成记忆和 Skills，任务可以从 CLI、消息渠道或自动化入口到来。“会越用越懂你”在工程上主要意味着保存并重新使用材料，不是每聊一次就训练模型权重。 README

普通知识工作者还应认识的相邻产品

完全不想管理 Provider、运行环境和工具的人，也应比较原生托管工作产品，例如 ChatGPT Work、Claude Cowork。它们把模型、连接器和工作空间作为一套产品提供；与自由换模型的 Harness 相比，更接近整套办公服务。Claude Cowork 的官方说明强调围绕文件与应用执行工作；ChatGPT 的能力和模型则按具体产品与账户开放。Cowork、OpenAI 官方产品文档

Manus 的官方资料还描述了持续运行的云端计算环境，属于值得关注的相邻路线。Cloud Computer Genspark、Perplexity Computer、Kimi 的办公产品，以及各类 AI 应用生成器，也处于相邻市场。但本次没有对它们全部建立同等级源码／架构证据，因此不把它们混进“已深读的开放 Harness”数量。对于只想完成一份报告的用户，选择托管产品往往值得考虑；对于要研究和替换代理内部结构的人，开放 Harness 更合适。

同样，LM Studio、Ollama 主要帮助运行和服务模型；SillyTavern 等更偏创作／角色对话；LangGraph、AutoGen、CrewAI 等偏开发框架。它们可能进入一套完整方案，但不应与开箱即用的代理产品在同一张总分表里硬排高低。
