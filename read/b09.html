B09 Amp：把能力档位定义为一整套执行配置

定位与设计理念

Amp 当前的 low／medium／high／ultra 不只是更换模型。每档组合了模型、推理强度、系统提示、工具和 Oracle 等能力。它体现了一种产品判断：用户选“这个任务值得投入多少能力”，具体执行组合由产品组织。模式与模型

Amp 将任务投入做成可选择的能力档位，减少用户逐项配置模型参数的负担。档位可能同时改变模型、推理强度、工具和专家调用。这样能降低调参负担，但也意味着两次不同档位的比较，不是严格的单模型实验。产品替用户做了一部分编排决策，用户仍要判断这些额外能力是否值得。

工作原理与架构图

Search、Oracle、Librarian、Read Thread 等专门处理代码检索、难题推理、外部资料和历史任务。它们通常拥有独立上下文，主代理收到汇总；文档明确区分这种分工与可彼此随意沟通的团队。Orbs 则扩展到持久远程工作环境。工具、Orbs 入门

主代理遇到难题时可以咨询 Oracle，调查外部材料时使用 Librarian，检索代码则有其他专门能力。这些职责通常交回结论，帮助主对话避免被大量中间过程占满。它们不是必然彼此通信的一个团队。升档增加的能力可能减少返工，也可能对简单任务产生额外调用，因此可以结合总耗时、调用量和人工纠正次数评估升档收益。

深入一层：主模式、专用子代理与模型角色

Amp 官方把模式描述为模型、推理强度、系统提示、工具与辅助角色的组合。主代理推进任务，专用子代理在自己的窗口处理一部分工作，Oracle 等角色承担困难推理或规划。因此选择模式不等于只在下拉框换一个模型，辅助调用也属于整项任务的运行路径。

模块／交接点 怎样工作 状态与边界
模式组合 角色和工具策略随模式一起变化 比较模式时不能把结果差异全部归因于模型。
独立窗口 子代理隔离其长调查上下文 交接遗漏仍会影响主任务判断。
辅助角色 支持性模型处理特定工作 总成本应包含这些调用与重试。

沿着一次任务看数据怎样走。 例如复杂迁移：主代理协调实施，专用调查找出旧 API 使用点，困难设计问题交给分析角色。最终仍由任务验收检查是否遗漏调用方；多个角色给出一致意见并不构成正确性证明。

与相近工具的实质差别。 与用户逐个配置 Provider 的开放终端工具相比，Amp 更强调产品化的角色配方。它降低搭配成本，同时减少使用者对每次内部模型分配的控制。

能力、状态与边界

观察项 实际机制／公开能力 对使用者意味着什么
能力档位 low／medium／high／ultra 等组合配置 档位不只是模型名或单一推理参数
专家分工 Search、Oracle、Librarian 等 核对角色实际职责，不按名称幻想权限
上下文 专门任务与主任务之间进行汇总 交接需要证据和文件位置，不能只有结论
历史 Read Thread 等历史访问能力 历史可访问不代表每轮自动全部读入
远程环境 Orbs 等持久工作路线 另检查环境、凭据与生命周期
可复现性 官方路由可能随产品更新 记录档位、实际模型、工具配置和版本

把机制放进实际工作。

能力档位是一组产品决策。升档后不仅可能思考更多，还可能调用不同专家或采用不同工具。因此，比较档位是在比较完整配置，而不是孤立测模型智力。记录实际调用与结果，才能解释更高档究竟改善了哪一步。

独立上下文的专家适合处理边界清楚的问题。向 Oracle 提问“这段并发控制的两个假设哪个更符合日志”，通常比让它泛泛审查整个项目更容易得到可用结论。交回的依据必须让主代理能继续核验，否则专家只是又一层听起来权威的回答。

历史访问和持久远程环境解决不同连续性问题：前者找回曾经讨论的材料，后者保存工作现场的某些条件。两者都需要核对现状，不能把旧线程说服务正常当作当前环境正常。小任务不必使用全部能力，减少无效专家调用有时比单纯换便宜模型更有帮助。

从安装到完成第一个任务

  1. 按官方入门选择入口，先用中等能力档位做一项你熟悉的任务，保存完成结果与成本。

  2. 任务中要求指出依据和验收；观察主代理在什么情况下调用专门能力，以及汇总是否真的帮助推进。

  3. 对确实失败或困难的环节升档，比较是否减少错误或人工干预，不仅比较措辞与推理长度。

  4. 需要持久远程环境再配置 Orbs；先验证项目运行、资料可用性和结果保存，而不把远程环境等同于更强模型。

  5. 再考虑插件或自定义分工，清楚规定输入、输出和工具；保留标准档位任务作为升级后的回归基线。

调查一个偶发并发错误，给出可验证的根因、最小修复和回归测试。需要额外推理时说明要咨询的问题，交付时保留支持结论的代码证据。

困难调试适合检验专家分工。重点看咨询是否提出了新且可验证的假设，主代理是否据此重现并修复；多个角色重复同一句猜测不能算相互验证。

模型搭配、适用方向与取舍

首选“任务档位＋当前官方路由”，并记录实际模型；需要固定模型或 BYOK 时按当前文档配置。其路由会更新，因此不能长期宣称 Amp 永久绑定某一家模型。适合希望减少自行调参、又需要专家分工的熟练开发者。难度：中；自定义编排中高。
