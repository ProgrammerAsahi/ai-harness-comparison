C03 Agent Zero：给代理一套可以动手操作的工作环境

定位与设计理念

Agent Zero 偏向通用任务代理：让模型在可操作的计算环境中使用工具、编写程序、处理资料和分派任务。提示、工具、扩展和工作空间可以被用户修改，因此它兼具产品与实验平台的性质。README

Agent Zero 把模型放进能实际操作的计算环境，使它可以写程序处理资料、调用工具并分派工作。它更像通用技术助理实验台：适应任务的方式很多，用户也能修改提示和工具。自由度越高，越需要清楚提供资料范围、输出要求与可操作环境，否则模型容易花很多时间探索而没有形成可用结果。

工作原理与架构图

下图结合所引源码与文档，画出本工具的主要责任分工；为便于理解，省略次要模块与错误分支。

agent.py 的循环反复准备提示、调用模型、处理工具，并在多个节点触发扩展与用户干预。子代理通过上下级关系和独立配置组织，具体任务可以交给不同职责的下属。这套设计容易扩展，但扩展一多，排查行为变化也更费力。主循环、下属代理

主循环在准备提示、调用模型、处理工具等位置允许扩展介入，适合试验不同工作方法。下属代理拥有自己的配置与任务，主代理负责交接和汇总。容器给任务提供相对独立的环境，但挂载目录和外部凭据仍决定它能影响什么。最实用的验证是检查最终文件与计算过程，而非仅听代理说它调用了很多工具。

深入一层：AgentContext、上下级代理与执行环境

Agent Zero 中，AgentContext 管理任务级状态，Agent 则有自己的推理和对话过程；call_subordinate 建立上下级工作关系。层级分工能把复杂目标拆小，但不能把每个子代理都看成天然独立的机器。实际文件、工具环境和资源的共享范围，仍要按部署及调用方式判断。

模块／交接点 怎样工作 状态与边界
Context 与 Agent 任务级管理和单个代理职责分开 重置或移除上下文的影响可能超出一条消息。
上下级交接 上级给任务，下级返回可用结论 任务范围不清会增加重复调查和无效层级。
系统工具 代理通过环境完成实际动作 有代码执行能力就需要关注环境，而不是只看聊天权限。

沿着一次任务看数据怎样走。 例如汇总多个目录的数据：主代理确定格式与验收，下级分别调查数据结构，再回传结论；主代理执行合并并检查输出。若下级也改同一份产物，应先分配写入责任，否则层级结构并不会防止冲突。

与相近工具的实质差别。 与固定角色团队相比，递归式上下级结构更灵活，也更需要控制任务深度、预算和状态共享；与 mini-SWE-agent 相比，任务管理层明显更厚。

本节细图与机制依据：agent.py、call_subordinate.py、README.md。箭头表示主要信息或控制交接，不表示所有分支必然并行；省略的模块不能视为不存在。

能力、状态与边界

观察项 实际机制／公开能力 对使用者意味着什么
通用执行 文件、程序、资料与工具操作 输出应是可检查产物，而非操作数量
可修改性 提示、工具和扩展可调整 逐项改动，保留最小稳定配置
子代理 上下级关系与独立配置 需要明确任务输入、证据和汇总责任
执行环境 容器或文档支持的环境 挂载与凭据仍可让任务访问宿主和外部服务
用户干预 循环中的反馈与扩展节点 纠正后确认旧计划和新要求已对齐
模型要求 多轮工具、纠错和代码执行 小模型是否稳定要通过任务验证

把机制放进实际工作。

通用计算环境可以通过临时脚本处理复杂资料，这是它与纯聊天的重要差别。脚本产生数字时，应保留输入、筛选条件、计算方法和失败文件清单；模型最后的解释需要依据这些结果。能运行程序带来可验证性，也要求用户真正利用这些证据。

扩展在多个循环节点介入，会让定制更灵活，也增加行为来源。某次修改提示或工具后质量下降，应从最小配置重现，逐项恢复；同时更换模型和多个扩展，会使原因难以判断。子代理继承哪些背景、使用哪份配置，也应写进记录。

容器隔开部分运行环境，实际影响范围仍取决于挂载与授权。把全部个人目录和广泛业务凭据放进去，会改变原本期待的边界。先给任务专用输入与输出目录，完成后检查产物，再逐步增加能力，更容易理解每项工具到底贡献了什么。

从安装到完成第一个任务

  1. 按官方方式准备运行环境，核对挂载目录与模型配置；使用测试材料，先验证文件输入和结果保存。

  2. 给出一项有明确输出的资料任务，例如整理一批文档并生成索引，说明来源、格式和不能推测的事实。

  3. 检查代理生成的程序与中间结果。统计任务至少用已知样本复算，确认工具执行不是只做形式上的处理。

  4. 需要分工时按材料或职责拆成独立子任务，要求保留证据位置；主任务负责去重、冲突处理和最终结论。

  5. 基础流程稳定后再改提示和扩展，并记录差异。无人值守使用前另测中断、失败和重复执行，确保文件与状态可恢复。

模型搭配、适用方向与取舍

优先能稳定处理工具、多轮纠错和代码执行的模型，如当前适配的 Claude／GPT；成本方案再比较开放模型。复杂编排对小模型的稳定性要求高，不宜只按每百万 Token 单价选择。适合技术用户的资料处理、自动化、通用代理实验。难度：中高；无人值守部署高。

选择路线 候选组合 怎样决定
执行基线 已适配的可靠 GPT／Claude 工具模型 先完成文件、检索、计算和错误恢复，建立可信基线。
中文与成本 兼容服务中的 Qwen／DeepSeek 等候选 先核对接入文档并测试工具往返；通用接口兼容不等于完整模型适配。
本地试验 正确服务的开放模型 先测短任务和多轮调用，复杂长任务另行验收。

适合技术用户处理复杂资料和试验通用代理。丰富的可修改性带来更高排错成本，容器管理也需要基本工程能力。普通写作可以用更轻客户端；明确固定流程可用 Dify；复杂临时任务才更能体现这一类环境的价值。
