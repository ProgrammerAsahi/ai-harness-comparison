D02 n8n：让代理进入已有的业务自动化

定位与设计理念

n8n 的起点是连接应用与触发流程，AI Agent 是其中可配置的节点。当前 Tools Agent 执行器建立模型、记忆、批处理等上下文，再将工具执行交还工作流引擎并接续结果，同时记录执行次数、失败类型和记忆读写等追踪信息。README、Tools Agent V3

n8n 从业务自动化出发，AI Agent 是流程中的一类节点。表单、计划或应用事件先触发任务，流程把数据交给模型判断，再连接其他系统。这适合重复发生、输入输出位置明确的工作。模型处理语义不确定性，流程负责固定顺序；把二者分开，可以减少让模型自行决定全部业务动作的负担。

工作原理与架构图

下图结合所引源码与文档，画出本工具的主要责任分工；为便于理解，省略次要模块与错误分支。

这与终端代理最明显的差别在于“什么时候开始做事”：可以由表单、计划、Webhook 或应用事件触发；输入输出已经是业务数据。模型负责有不确定性的环节，外层流程负责顺序与交接。

模型可以决定调用哪个已暴露工具，而实际工具执行仍与工作流引擎衔接。引擎继续传递结果并保存运行状态，使排错能够定位到具体节点。自动重试需要格外考虑重复副作用：一次创建工单已成功、回执却丢失时，直接重跑可能创建两份。可以用业务唯一标识检查是否已经处理过，为重试提供可核查的依据。

深入一层：工作流引擎如何接管 Agent 的工具执行

n8n 的 Tools Agent V3 将代理决策与工具执行分开衔接。代码会组织批次和模型／记忆输入，把工具请求交给引擎执行，再消费返回的 actionResponses；同时记录迭代、调用和记忆读写等信息。这样 Agent 的自主判断仍嵌在可观察的工作流执行体系中。

模块／交接点 怎样工作 状态与边界
数据批次 输入以 items 进入，按批次处理 一个输入与多个输入的字段处理可能不同。
工具交接 Agent 提出请求，引擎执行后回传结果 超时和重试要考虑已经发生的业务动作。
执行记录 节点结果与追踪信息帮助定位失败 模型 Token 少不代表整个流程运行成本低。

沿着一次任务看数据怎样走。 例如每周工单汇总：校验节点确定时间范围，Agent 整理语义，后续节点存储审阅后的报告。若重复触发，先按周期标识查已处理记录；否则流程重试可能重复创建报告，即便生成内容完全正确。

与相近工具的实质差别。 与 Dify 相比，两者都有外层流程与内层 Agent，n8n 更突出事件、业务数据和应用连接；与纯代理循环相比，它要求提前设计字段与失败路径。

能力、状态与边界

观察项 实际机制／公开能力 对使用者意味着什么
启动方式 计划、表单、Webhook 与应用事件 触发频率和输入质量影响整个系统
固定流程 节点、变量与状态记录 关键业务顺序应由流程明确表达
代理节点 模型、记忆、工具及批处理 限制为该任务需要的工具
连接器 跨应用读取和写入 核对账户身份、字段和授权范围
失败恢复 节点执行与错误追踪 重试前考虑重复创建、重复发送等副作用
许可 官方 fair-code 路线 源码可见不意味着任何商业用途都无条件开放

把机制放进实际工作。

自动化的核心问题之一是重复。网络超时可能发生在动作已成功之后，因此重试前需要业务标识或状态检查。让模型承诺不重复，无法替代确定的去重逻辑。创建记录、发送消息和更新状态尤其需要清楚的恢复设计。

字段与批量数据也容易出错。上游返回空数组、多个对象或不同日期格式时，下游节点可能收到与预期不同的输入。先检查节点数据和转换，再判断模型是否理解错误；把所有结构问题包装成自然语言交给模型，会降低流程可解释性。

Agent 节点适合处理需要理解的局部工作，固定业务顺序由工作流管理。逐步从手动触发到定时运行，可以把内容质量、流程正确性与长期可靠性分开验收。成本除了模型，还包括连接器配额、运行资源和处理失败的人工时间，长期任务尤其需要这本总账。

从安装到完成第一个任务

  1. 从手动触发开始，连接一个测试数据源和模型，先跑“读取→生成草稿→人工检查→保存”的最小流程。

  2. 明确定义每一步字段，检查数组、空值和日期格式，避免模型把结构错误写成自然语言解释后继续执行。

  3. 在 Agent 节点只配置所需工具，先让它只读或生成草稿；外部写入放在能够审阅的后续步骤。

  4. 测试模型超时、连接器失败与重复事件，设置业务唯一标识和已处理记录；确认重跑不会重复写入。

  5. 最后才添加计划或 Webhook，配置运行记录与失败处理；每次改模型、凭据或节点后复测关键路径。

周报自动化的概念流程：
手动／定时触发 → 读取本周数据 → 校验字段
→ 模型生成草稿 → 人工审阅 → 保存最终文件
每周使用唯一周期标识，重复触发先检查是否已处理。

典型任务与验收方法

下面是一份可直接改写使用的试用任务，属于本报告设计的验收示例，并非已完成的运行测试。

每周汇总项目工单，生成进展与风险草稿，保留工单链接和统计口径。先等待人工确认，再保存到指定位置；同一周重复运行不生成重复记录。

用空数据、重复事件、连接器暂时失败和人工退回四种情况验证。报告写得好只证明其中一个节点工作，整条自动化还要证明输入准确、写入可控和失败可追踪。

模型搭配、适用方向与取舍

先做“读取数据→生成草稿→人工确认→保存”四步，再加自动触发。简单步骤试经济模型，复杂判断试更强模型；只有确认所用节点支持相应接口后才接入。适合每周报告、线索整理、工单分类、跨应用资料处理。难度：中；可靠生产流程高。官方称其为 fair-code，不应把可见源码直接解释成无条件的宽松开源许可。

选择路线 候选组合 怎样决定
简单节点 支持接口的经济模型 分类和固定提取先用样本验收，并设计无法判断分支。
复杂判断 支持的较强 GPT／Claude／中文模型 按节点升级，避免整条流程无差别使用最高档。
本地或组织 对应插件／节点支持的内部服务 检查结构化输出、工具参数、失败重试与总成本。

适合跨应用、重复触发和字段明确的业务工作。代价是流程、凭据和失败分支维护。模糊的一次性研究可用通用代理，固定资料应用可用 Dify；先判断任务是否会重复，再决定值得投入多少流程搭建工作。
