B15 腾讯 CodeBuddy：面向中文开发生态的多入口代理

定位与设计理念

CodeBuddy 覆盖 IDE、插件和 CLI；其上下文入口包括文件、代码片段、文档、Git 与终端。对微信小程序、腾讯云相关开发者，现成资料入口和中文工作流有实用价值，但这不等于其他项目不能用。上下文文档

CodeBuddy 把代理能力放进多种开发入口，同时面向中文和腾讯相关开发生态。对于已有小程序、云服务与团队工具链的用户，现成上下文入口可能比自己拼装连接器更方便。它的价值应在真实项目中衡量；国内、国际、IDE 和 CLI 各自提供什么，不能只凭共同品牌推断。

精确引用报错、Git 变更和文件，可以帮助代理从正确位置开始；如果上下文没有指向真正模块，中文对话再顺畅也可能改错。CLI 自定义子代理把一类职责独立保存，主代理调用后获得汇总。工具和权限可能存在继承关系，因此“新建一个研究角色”并不天然意味着只读，要核对最终工具集。

深入一层：产品入口、项目工具与模型渠道

CodeBuddy 的公开能力应按具体入口、地区和账户理解。较细一层可以确定的是：用户资料要进入上下文，模型产生工具意图，工具在相应环境执行，再把观察送回任务。图采用这种公开接口级拆解，不给尚未公开的内部调度器、存储引擎或压缩算法杜撰名称。

模块／交接点 怎样工作 状态与边界
入口与环境 IDE、其他客户端或服务对应不同使用条件 先确认当前入口支持的工具与执行位置。
模型渠道 模型选择经过产品提供的接入方式 一个渠道能聊天，不证明所有 Agent 功能等价。
结果检查 任务输出应与代码变更和运行结果对应 界面成功提示不能代替具体行为验收。

沿着一次任务看数据怎样走。 例如修复业务规则：提供受影响模块与不能改变的行为，让代理读取实现、修改并检查。若想换模型，应在同一入口、相同初始代码和权限下重做任务，才能更清楚地比较差异。

与相近工具的实质差别。 与能够逐文件分析的开源循环相比，这里的内部证据较有限；与其他商业开发工作台相比，入口、渠道及实际执行边界比模型列表长度更有选型价值。

能力、状态与边界

观察项 实际机制／公开能力 对使用者意味着什么
产品入口 IDE、插件和 CLI 功能与模型按版本和地区分别核对
上下文 文件、代码片段、文档、Git 与终端 优先提供与问题直接相关的材料
子代理 独立职责、上下文与工具配置 检查继承后的有效权限
扩展路线 团队、工作树、沙箱与 SDK 文档 可用性以对应入口说明为准
生态 中文及腾讯相关开发场景 生态熟悉度不能替代项目实际验证
商业边界 完整运行时未公开 不推断内部一定使用某款竞品核心

把机制放进实际工作。

上下文引用可以减少代理猜测，但要选择正确证据。报错来自运行时，Git diff 描述最近改动，接口文档说明预期契约，三者各有作用。代理需要把它们联系起来，而不是只因为某个文件最近改过，就认定它一定是根因。

子代理的职责与权限应一起定义。“研究员”可以要求只返回结论，却仍可能继承命令工具；真正只读需要对应执行限制。团队或工作树功能则另涉及目录、取消与结果集成，不能由一个角色配置文件推断全部能力。

相关生态可以减少查找资料和配置入口的成本，但实际项目仍可能使用不同 API 版本或自定义组件。让代理对照当前依赖与真实输出验证。国内外版本、插件和 CLI 的模型及额度也应分别记录，避免把一个入口的成功经验直接当作整个产品家族的承诺。

从安装到完成第一个任务

  1. 选定国内或国际版本及一个入口，完成登录与模型配置；查看实际权限，确认账单和组织政策。

  2. 打开真实项目，显式引用出问题的文件、终端输出或 Git 变更；让代理先说明调用关系和运行方法。

  3. 给出最小修复任务，保持业务边界清楚。涉及小程序或云服务时，用项目实际配置和官方接口资料核对实现。

  4. 需要反复进行同类调查时，再在 CLI 建立职责清楚的子代理，检查其工具和权限，而不只看角色描述。

  5. 完成后检查代码、运行结果和部署假设。需要团队或工作树再逐项试验，不把另一个入口的教程直接套过来。

模型搭配、适用方向与取舍

以当前版本实际提供的模型和自定义接入为准，优先产品默认路线；需要固定模型时先验证工具调用。适合中文团队、小程序、腾讯云相关开发以及希望兼顾插件和 CLI 的人。难度：低中。WorkBuddy 属于扩展到办公任务的相邻产品，不能用它的能力反推所有 CodeBuddy 入口。

选择路线 候选组合 怎样决定
生态基线 当前版本默认或可选模型 先验收相关项目和工具，地区目录分别记录。
困难开发 入口允许的更强工具模型 以重现、修改、测试的完整结果判断。
自定义路线 仅使用明确支持的服务配置 不凭国际版或另一入口的文档推断可用性。

适合中文团队、相关云生态和希望兼顾插件与 CLI 的用户。优势是现成整合，代价是地区、入口与配置差异。复杂多模型研究更适合开放底座；单一生态开发则可能因少配一些东西而节省更多时间。
