B18 CodeCompanion.nvim：把模型适配和完整代理接入明确分开

定位与设计理念

CodeCompanion 提供对话、局部转换、代码审查、工具和工作流，同时保留较强的编辑器配置自由。它适合希望在 Neovim 内按自己的习惯组合 AI 能力的人。README

CodeCompanion 把 Neovim 当作可组合的 AI 工作台，提供聊天、局部转换、审查与自定义工作流。它清楚区分模型适配和代理连接，使用户可以按任务选择：简单转换直接请求模型，复杂开发交给完整代理。灵活性很高，但用户要愿意明确每条路线的责任和配置。

工作原理与架构图

下图结合所引源码与文档，画出本工具的主要责任分工；为便于理解，省略次要模块与错误分支。

HTTP Adapter 处理模型请求、响应和工具格式；ACP Connection 处理外部代理的会话、能力、权限请求和流式更新。前者是“自己组织对话并请求模型”，后者是“把完整任务交给另一个代理”。两者都出现在同一编辑器里，但负责执行的人不同。HTTP 适配、ACP 连接

HTTP Adapter 处理的是向模型发请求、解析流和工具格式；ACP Connection 处理的是与一个会自己执行任务的代理交流，包括会话更新与权限请求。前者类似给模型接插座，后者类似接一位完整同事。排错时先辨认这层边界：模型参数不支持与外部代理无法启动，不应采用同一种修复办法。

深入一层：HTTP 模型适配与 ACP 代理适配的双路线

CodeCompanion 的 HTTP 与 ACP 适配层连接的对象不同。HTTP 连接的是模型接口，宿主需要组织工具调用；ACP 连接的是已经带有自身工具和会话逻辑的代理进程。两种配置都可能显示为聊天，但执行权、认证和恢复责任的位置不同。

模块／交接点 怎样工作 状态与边界
HTTP 路线 模型服务返回生成内容与工具意图 插件和配置需承担相应执行组织。
ACP 路线 独立代理通过协议与编辑器沟通 模型和原生设置可能由外部代理管理。
共享界面 同一编辑器呈现不同运行路线 不能因为 UI 一样就沿用另一条路线的权限结论。

沿着一次任务看数据怎样走。 例如同样让它修改一份配置：HTTP 路线要检查插件工具是否开放，ACP 路线要检查外部代理是否登录、是否有访问工作区的权限。排错从适配入口开始，能避免反复修改无关的模型字段。

与相近工具的实质差别。 与 Avante 的直接代理能力相比，CodeCompanion 的双适配边界尤其值得单列；与 Zed 类似，编辑器可以是代理宿主，而不必拥有对方完整运行时。

本节细图与机制依据：init.lua、init.lua、README.md。箭头表示主要信息或控制交接，不表示所有分支必然并行；省略的模块不能视为不存在。

能力、状态与边界

观察项 实际机制／公开能力 对使用者意味着什么
交互 Chat、局部转换、审查和工作流 根据编辑尺度选择，不把所有操作变成长任务
HTTP Adapter 模型消息与工具格式适配 兼容服务需核对参数和返回格式
ACP Connection 外部代理会话、能力及审批 代理模型与权限在相应后端配置
规则和扩展 可按需接规则、Skills、MCP 等 配置越多，越需保留最小可用基线
运行责任 插件与外部代理分工明确 同一界面下可能有不同状态保存方式
维护 编辑器、插件和后端共同变化 升级分批进行，便于定位失效层

把机制放进实际工作。

一个轻量转换不一定需要完整代理。例如改写注释或转换选中代码，直接模型请求可能已足够；需要读多个文件、运行检查并纠错时，再使用完整工具循环或外部 ACP 代理。按工作尺度选择，能减少等待和不必要的配置。

自定义工作流应写清输入和输出，特别是结果应用到哪个缓冲区、是否允许跨文件修改、错误时怎样结束。一个漂亮提示模板如果没有这些约定，重复运行也可能产生不同副作用。先固定少量高频工作流，比把社区配置全部装进来更容易维护。

排错可以按编辑器、适配器、外部代理与模型四层进行。先确认选区和项目路径，再确认连接与认证，最后看工具与模型结果。只在 HTTP 路线正常，不能证明 ACP 路线也已配置好；反过来，外部代理本身可运行，也不能保证编辑器传递了正确上下文。

从安装到完成第一个任务

  1. 安装符合当前要求的插件，先选 HTTP 或 ACP 一条路线；完成对应认证，确认简单提问能返回结果。

  2. 从局部转换开始，如解释函数或改写注释，检查选区与输出插入方式；熟悉后再处理文件级修改。

  3. 将重复提示整理成工作流，明确输入、输出和可用工具。不要一次添加所有社区配置。

  4. 复杂任务接外部代理时，先在其自身入口验证，再通过 ACP 连接，检查审批、工具结果和会话结束能否正确呈现。

  5. 升级或切换后端后，用相同小任务检查上下文、修改应用和权限；把工作流配置与模型版本一起记录。

典型任务与验收方法

下面是一份可直接改写使用的试用任务，属于本报告设计的验收示例，并非已完成的运行测试。

为选中的函数写清楚输入、输出与异常说明，再检查一个实际调用方是否违反约定。只在确认错误后做最小修复并解释 diff。

这个任务先用轻量转换，再进入项目检查，能帮助判断何时需要完整代理。核对插件是否传入正确选区，外部后端是否获得调用方文件，以及两条路线的结果能否在编辑器中清楚审阅。

模型搭配、适用方向与取舍

安装插件后，先在 HTTP 模型与 ACP 代理两条路线中选一条。局部变换可以使用较快模型；复杂任务可接 Codex／Claude Code 等原生代理。再按需添加 MCP、规则和 Skills，避免一次改变整个配置。适合 Neovim 用户、自定义提示与工作流爱好者；模型和多入口配置成本较高。难度：中高。

选择路线 候选组合 怎样决定
直接模型 插件已适配 Claude／GPT 等 局部转换可用较快档，复杂编辑优先工具稳定。
完整代理 ACP 接 Codex／Claude Code 等 模型、认证与权限沿外部代理配置。
本地或经济模型 已通过工具测试的兼容服务 先从选区与短任务开始，记录格式与补丁错误。

适合喜欢定制提示和编辑工作流的 Neovim 用户。优势是责任边界清楚、组合自由；代价是配置和多层排错。若希望少做配置并直接接受 AI 修改，可比较 Avante；若只想完成任务而不维护编辑器，应选择其他成品入口。
