# 第一轮试编码记录（码本 fields-0.2）

这一页记录第一轮试编码怎样做、两位编码者有多一致、结果能说明什么。逐字段的分歧随时可以复算：

```bash
python3 studies/harness-quantification/compare_codings.py
```

这一轮的编码结果是两位编码者各自独立的初稿，还没有对过分歧，也没有人工裁决。它们用来找码本定义的缺口，不是对任何工具的评分，也不进入方法报告正文。

## 怎样做的

- 对象：10 个配置记录（`data/configs/`），版本和提交都钉在 2026-11-10。
- 码本：`data/schema/fields.json` 的 `fields-0.2`，36 个字段。
- 编码者 `opus`：Claude Opus 5.5。Claude Code、Codex、Kimi Code 三个配置用任务卡 `coding-card-v2`，其余七个用 `coding-card-v3`；两版的差别只是 v3 多一段“不能联网的环境”。
- 编码者 `gpt`：GPT-6.1 Sol，全部用 `coding-card-v3`。型号按派活时请求的型号记录，运行环境没有回报实际型号。
- 两位编码者互不可见。每个配置分三段（字段组 ABC、DEF、GHI），一段一次独立运行，共 60 次；每段交回后由 `pilot/parts.py check` 检查，再合并成 `data/codings/<编码者>/<配置>.json`。
- 都只读公开资料，不安装、不运行被研究的工具。

## 两位编码者读到的材料不一样

`opus` 能联网，按钉住的提交在线读仓库和官方文档。`gpt` 在不能联网的环境里运行，只读 `pilot/fetch_sources.py` 按同一提交取到的源码快照；官方文档不在仓库里的两个工具（Claude Code、Codex）另附文档站自己发布的全文导出。

所以“一方找不到证据、另一方找到了”的分歧，有一部分来自材料不对等，不全是定义问题。这一轮状态不同的 11 处，全部是 `gpt` 记“未知”而 `opus` 记了取值，其中 5 处在闭源的 Claude Code 上。下面的一致率没有扣除这一层影响。

## 一致率

一致率是“两位编码者状态和取值都相同的字段数 ÷ 36”，没有做随机一致的校正；每个配置只有一对编码者。

| 配置 | 一致 | 取值不同 | 状态不同 |
|---|---|---|---|
| A01 Claude Code | 53% | 12 | 5 |
| A02 Codex | 61% | 13 | 1 |
| A05 Kimi Code | 64% | 13 | 0 |
| A06 MiMo Code | 72% | 10 | 0 |
| A07 DeepSeek Harness | 61% | 14 | 0 |
| A08 OpenCode | 58% | 14 | 1 |
| A09 Pi | 75% | 9 | 0 |
| A10 Cline | 83% | 4 | 2 |
| A17 Step Code | 67% | 12 | 0 |
| C02 OpenClaw | 56% | 14 | 2 |

合计 360 个“字段 × 配置”里 234 个一致（65%），115 个取值不同，11 个状态不同。

按字段看，10 个配置上全部一致的有 F01（主取值）、F07、F18、F25；一致最少的是 F32（0%）、F29（20%）、F10 和 F31（各 30%）、F14 和 F17（各 40%）。带分面的五个字段里，分面不一致的有 F01（10 个里 4 个）、F12（30 个里 9 个）、F21（40 个里 3 个）、F23（10 个里 4 个），F22 的 20 个分面全部一致。两位编码者一共提了 15 条词表补充建议。

## 能说明什么

- 这是码本第一次用在真实工具上。65% 的原始一致率说明不少字段的定义还不足以让两位编码者得出同样的答案；一致率低的字段是下一步修订码本的重点（方法报告 14.1）。
- 一致不等于正确：两位编码者可能错在同一处。不一致也不说明哪一方错。
- 样本只有 10 个配置、一对编码者，不足以给单个字段的可靠性下结论。
- 修订码本后要重新编码，这一轮的结果届时作为历史记录保留。

## 这一轮之后改过的配置记录

两位编码者的说明里，有几处指出配置记录和钉住的源码对不上，或者两人对同一事实说法相反。这一轮结束后对照同一提交的源码核对，改了五份配置记录，各补了一条证据卡。这一轮的编码是照改之前的记录做的，下一轮照改过的记录。

| 配置 | 改了什么 |
|---|---|
| Codex | 入口补上：交互界面默认启动或复用一个共享的后台 app-server 守护进程，经本地套接字连接 |
| Kimi Code | 权限模式补上：POSIX 系统的 Git 工作树里，写入路径都在工作区内的文件编辑由内置策略直接放行；官方文档写的是编辑要确认 |
| MiMo Code | 内置工作流从“默认扩展”改为“随包带有、默认不启用”，要设环境变量才开 |
| OpenCode | 默认扩展补上内置的 Code Mode `execute` 工具 |
| OpenClaw | 说明里“启动时加载 18 个插件”改为：18 是声明启动时加载的个数，实际加载数随平台和配置变化（这部分读代码推断，没有运行验证） |

核对只读源码和文档，没有安装或运行这些工具。
