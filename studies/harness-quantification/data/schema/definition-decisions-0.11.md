## 一、负责人认可的四条（2026-11-25）

### 1. F03、F12：循环定时任务的到期期限

- 情况：A06、A16 各有一位编码者把“循环定时任务创建 7 天后自动到期”记成 F03 的 `budget` 和 F12 的 `time`。同一机制在 A01、A04、A05、A11、A17、A18 都没有据此记 `budget`。
- 读法（lead 条目 A06 F03、A06 F12、A16 F03、A16 F12）：
  - 到期期限管的是触发来源以后还会不会触发，不是一次任务的用量阈值，所以 F03 不记 `budget`。
  - F12 的 `time` 只计一次任务、一轮或一个会话的总时长，按同一口径也不记。
  - 对照时查过全部 F03 含 `budget`、F12 含 `time` 的配置。C02 的 48 小时是每次模型尝试的执行上限，属于正当的时长上限，不受影响。
- 写入：
  - `fields[F03].vocabulary[budget].criterion` 追加：“循环或定时任务本身的存活期限（例如循环定时任务创建若干天后自动到期、不再触发），它决定的是这个定时触发以后还触不触发，不是任务的用量阈值，不算，写 value_note。”
  - `fields[F12].vocabulary[time].criterion` 追加：“循环或定时任务的存活期限（创建若干天后到期、不再触发）不算，写 value_note：它限的是触发来源还会不会再触发，不是一次任务、一轮或一个会话的时长；定时任务每次运行的时长上限照常计入。”

### 2. F32：只启动子进程或连服务的官方 SDK

- 情况：总则 R5 说，满足构件库前提的官方构件库“F32 记 library”。F32 `library` 判定句又说，只包装网络或子进程调用的客户端库按背后的边界记。A01 的 SDK 和 B14 的三种 SDK 都是启动本机命令行程序、经标准输入输出交换任务，两句话指向不同的取值。
- 读法（lead 条目 A01 F32、B14 F32）：
  - 按 F32 的字段条款记背后的边界 `cli_subprocess`，不另记 `library`。字段条款和 R5 那一句冲突时，按 R7 以字段为准。
  - `library` 末句的例外（背后的本机服务没有线协议文档、官方只给 SDK）照旧，它只管本机服务，不管子进程。
  - A01、B14 的 F29、F31 里，按 R5 记入的 SDK 工具声明和回调不跟着改（负责人 11-27），条文写明这两个字段仍照 R5。
- 记录里的对照：
  - 同类记法一致的：B10 已按此记；A02、A04、B08、B09、A18 也一致。
  - 不受影响的：A08、A09、A10、D03、D04、C01、A03 的 SDK 在调用方进程里跑循环，记 `library`；D05 属本机服务例外；B01 的桥接另有公开协议，记 `service_api`。
  - B12 复核后改按本机服务例外记 `library`，见第五节。
- 写入：
  - `fields[F32].definition.scope_rule` 在“官方构件库按总则 R5 关于官方构件库的一句记”之后插入：“（只启动本核心子进程或连到本核心服务的官方 SDK 除外，见 library）”。
  - `fields[F32].vocabulary[library].criterion` 在“只包装网络或子进程调用的客户端库，按它背后的边界记服务 API 或 CLI 子进程；例外见本条末句。”之后插入：“官方 SDK 即使满足总则 R5 构件库的前提，只要它只是启动本核心的子进程、或连到本核心的服务来跑代理循环，就按背后的边界记 CLI 子进程或服务 API，不另记本项；子进程的标准输入输出协议没有单独文档的，也这样记。下面的‘例外’只管背后是本机服务、没有线协议文档的情形，不管子进程。这一句优先于总则 R5 里‘F32 记 library’的说法（总则 R7）；R5 所说三个字段一致记入，在这种 SDK 上只对 F29、F31 成立，它开放的工具声明和回调仍照总则 R5 记入这两个字段。”
- 没有改 R5：R5 那一句仍管构件库的前提和 F29、F31。F32 的例外靠字段条款说明，按 R7 以字段为准。

## 二、对照中一致、按负责人 11-27 认可写入的条款

这九类在对照时各配置读法一致，码本没有写明；F11、F23 两条码本基本能定，各补一句。下面每条先写记录里用的读法和依据的配置，再写条文。

### 1. F33：官方示例扩展算不算外部事件入口

- 读法：
  - 发行版随附、或官方文档给出的示例扩展和钩子配置，用户放进默认开放的扩展点后，就能把框架外的事件逐条送进会话、让空闲会话开始新一轮的，按 R2 算添加内容，记 `external_event`。
  - 示例只演示定时触发或框架内部事件的，不记。
  - 只说扩展接口可以自己写、没有官方示例，也没有文档写明的监视机制的，不记。
- 依据：
  - A09、A17 计入：随包发布、文档写明的文件触发示例扩展，经 `triggerTurn` 发起新一轮。
  - B14 计入：桌面版钩子页的 FileChanged 事件，借命令行钩子页的监视路径和唤醒机制，用户写钩子配置属于添加内容。
  - B12 不记：SDK 只泛称可以响应事件，只有一个定时示例，文件变化只是更新日志里的一个类型名。
  - A08（监视在厂商云端，按范围规则排除）和 B04（服务端分批开放，按 R10）也不记，但依据的是另外两条规则。
- 写入：`fields[F33].vocabulary[external_event].criterion` 追加：“官方随发行版附带、或在官方文档里给出的示例扩展和钩子配置，用户放进默认开放的扩展点后，就能把框架外的事件（例如文件变化）逐条送进会话、让空闲会话开始新一轮的，按总则 R2 算添加内容，记本项；文档写明文件变化一类事件和监视路径的钩子配置，也算。示例只演示定时触发或框架内部事件的，不因此记本项。只说扩展接口可以自己写、事件可以触发，没有这样的官方示例、也没有文档写明的监视或订阅机制的，不记。”

### 2. F36：终端或标签页标题算不算消息通知

- 读法：
  - 标题内容改成表示需要人注意的（等待操作、完成、出错），按终端状态序列记 `message_notification`，并注明依赖条件。浏览器标签页标题比照终端标题处理。
  - 只显示进度、会话名或对话名的，不记。
  - 原句“只显示进度或标题的，不记”和新句说法相反，所以原句改为“只显示进度、会话名或对话名的，不记”（见第四节）。
- 依据：
  - 计入：A03（终端标题改为“需要操作”，裁决计入）、A15（浏览器标签页标题加完成或出错前缀，裁决计入）、A14（响铃并改标题）、A09、A18（状态序列）。
  - 不记：A06、A08（终端标题只显示会话名）、C07（标签标题里的计数属于界面内显示）。C04 的未读标记不是标题。
- 写入：`fields[F36].vocabulary[message_notification].criterion` 的原句改为“终端状态序列只在表示需要人注意（完成、等待输入、出错、被阻塞）时记；只显示进度、会话名或对话名的，不记。”，其后插入：“终端窗口标题和浏览器标签页标题照此判：标题内容改成表示需要人注意的（例如‘需要操作’，或加上完成、出错的标记），记本项，value_note 写明依赖终端或浏览器显示标题。”

### 3. F19：默认没有工具时记不记 `tool_results`

- 读法：`tool_results` 以默认工具为前提，按 R1、R2、R3 排除。它不像 `task_plan` 那样另有“不按第二档排除”的例外。
- 依据：
  - B18：默认工具为空，工具要用户在消息里用提及符号添加。裁决按第二档只记 `conversation`。
  - C07：默认的普通聊天不注册工具，要用户打开开关。
  - C05：钉住的默认型号不调工具，工具路径写“其他环境”。
  - C04、C06、C08、D01、B17 默认就有工具，记入。D02 默认模板接了工具节点，按添加内容记入。
- 写入：`fields[F19].vocabulary[tool_results].criterion` 追加：“本项以默认工具为前提：所选配置默认没有任何工具、要用户在会话里打开工具、用提及符号加工具或改设置之后才有工具结果的，按总则 R2、R3 不计，value_note 写‘可选：’；钉住的默认型号不调工具、换型号才有工具结果的，按总则 R1 不计，value_note 写‘其他环境：’。task_plan 里‘不按总则 R3 第二档排除’一句只管目标，不适用于本项。”

### 4. F20：框架在工作区外保存的状态版本史

- 读法：
  - 只计代理工作文件或会话本身的回退点。
  - 技能、记忆、知识库文档等附属资产的版本史不计。
  - 代理执行任务时读写的文件，放在框架为它准备的目录里的，仍算工作文件。判别看对象是不是任务要读写的工作文件，不看文件类型。
- 依据：
  - 不计：C02（技能工坊把学到的技能存档在工作区之外，第三读者不计 `workspace_snapshot`）；C06（技能和工具的版本史）、C08（文档版本史）、D05（记忆内部的 git 回滚）。
  - 计入：D01 构建沙箱主目录里放的是代理自己的工作文件，有版本恢复入口，记 `workspace_snapshot`。它的对象和前四个不同。
- 写入：`fields[F20].vocabulary[workspace_snapshot].criterion` 追加：“快照的对象要是代理执行任务时读写的工作文件，在钉住的工作区里、或在框架为代理准备的工作目录里（例如沙箱主目录）都算；框架为技能、记忆、知识库文档一类附属资产保存的版本史、存档或回滚，不算，写 value_note。判别看快照对象是不是这次任务要读写的工作文件，不看文件类型。”

### 5. F31：“官方有文档的入口”的宽严

- 读法：
  - 看挂处理器的入口本身。订阅接口或挂钩入口对所选发行版有官方文档的就算，API 参考、随包手册、公开包的类型声明都可以；具体事件名可以从源码补全。
  - 入口完全没写，或者只写在内部开发参考、只写给自家客户端开发者的说明里的，不算。
  - 这一句只管 F31。
- 依据：
  - 不算：B11（`agent run` 的 ndjson 输出在源码里有类型化事件，但官方文档这一节没有这种输出格式，第三读者记 known_absent）；A14（压缩事件只经应用服务器的事件流交出，文档只在仓库的开发参考页上，写的是自家交付的客户端，第三读者不计）。
  - 算：A06、A08（公开插件包的类型声明）；D04（官方 API 参考有挂钩入口，各方法只在源码里）；D01（随发行版的手册写明订阅事件流）；C05、C08（公开协议和 OpenAPI 流）。
- 写入：`fields[F31].definition.scope_rule` 在“证据要指向实际的事件名或订阅接口；规则文件和提示文字不算处理器。”之后插入：“‘官方有文档’看挂处理器的入口本身（钩子配置、插件或回调接口、事件订阅接口或事件流的输出格式）：入口对所选发行版有官方文档的就算，文档站、API 参考、随发行版的手册、公开发布的包里的类型声明都可以，具体事件名可以从源码补全；文档写了命令、却没写它的事件流输出格式或事件的，不算；入口只写在源码、仓库内部的开发参考，或者只写给自家前端、客户端开发者的说明里的，也不算。这一句只管 F31；F29、F32、F33 的入口要不要文档、要多明确，照各字段的判定。”
- 边界：D04 最靠近界线（只有入口有文档）。C05 引用的一份文档标着“重写目标”，版本是否对应存疑。这是事实问题，不由条文决定（第六节）。

### 6. F04：拒绝型钩子算不算模型自修

- 对照建议的读法：拒绝型钩子归 F23，不作 F04 的证据。这条建议来自 B21：Artifact 首次无链接发布时被前置钩子拒绝，对照材料认为这是约束，不是失败处理。
- 记录里实际用的读法：
  - 拦截本身记在 F21、F23。

### 7. F24：`intent` 的读法

- 读法：
  - `intent` 不按范围规则里“相邻”的要求。
  - 能在有序的持久记录里确定一个动作属于哪一条用户请求，就算对得上。
  - 一条请求之后、下一条请求之前的动作，都归这条请求。
  - 不要求一条请求只对应一次调用。
- 依据：
  - B14：第三读者认为，读者一把“唯一对上”读成了一条请求对一次调用，而判定的方向是“给定一个动作，能否唯一找到它的意图”。
  - A03、A06、A08、A13、C06、D01 按同样的读法记入。
  - B12：对话记录的格式没有文档，无法确认，不记。
- 写入：`fields[F24].vocabulary[intent].criterion` 追加：“这一项不按范围规则里‘相邻’的要求：触发动作的用户请求和动作在同一份按顺序写入的持久记录里，或经父消息编号相连，能确定动作属于哪一条用户请求的，就算对得上。按顺序写入的记录里，一条用户请求之后、下一条用户请求之前的动作都归这条请求；一条请求触发多次调用的，每次调用都对上这同一条请求。”
- A18 按新条文应补 `intent`，见第五节。

### 8. F28：`shared_board` 的边界

- 读法：要有一张由框架维护、有固定结构的任务表。各任务的结果、进度说明或交接内容（不只是运行状态）写在这张表里，调用方或协调者能从表里汇总。只列名册或状态、只供界面看、只有协调者写、会话私有的表，都不记。
- 依据：
  - 计入：
    - A06：任务表加上子代理写的进度文件，框架校验结构，并在检查点里按表整合，裁决计入。
    - A11：默认看板，子代理发结果帖，父代理读板汇总。
    - C03：任务完成时，框架把状态和最后结果写回调度表，调用方用列表和查看工具汇总，裁决计入。
    - C08：任务表含状态、进度和交接内容，裁决计入。
  - 不记：A14（只列运行状态）、A16（任务面板只供人看）、A17（会话私有的表，父侧名册只是显示）、D05（团队表只有主控写）。
  - C03、A06、A11 的结果同时经委派返回或通知交回，不影响计入。
- 没有写“持久”：对照材料的概括里写了“持久”，但记录里没有核对过 A11 的看板是否持久，所以条文不加这个条件。
- 写入：`fields[F28].vocabulary[shared_board].criterion` 追加：“判别要点：表由框架维护，有固定结构，由默认工具、接口或框架内置流程读写；派出的各代理（或框架替它们）把各自任务的结果、进度说明或交接内容写进这张表，不只是运行状态；调用方或协调者能用默认工具、接口或框架内置的汇总流程从表里汇总。只列代理名册或运行状态（运行中、完成、失败）的列表，只供界面显示的任务面板，只有协调者一方写、各代理不写的表，各会话私有的任务清单，都不记。结果同时经委派调用返回或通知交回的，不影响记本项。”

### 9. F25、F26：用户手动取回结果算不算交回

- 条文位置：用户开出的对话算不算代理、F26 记不记 `user`，取决于 F25 范围规则里“把结果交回发起它的会话或一个汇总界面”这个条件（F26 `user` 的判定句引用它），所以条款写在 F25。
- 对照建议的读法：用户手动取回结果不算交回，据此建议 B01 F26 去掉 `user`。负责人 11-27 维持了 B01 的裁决（理由是类比不同），所以条文要让 B01 成立。
- 记录里实际用的读法：
  - 算交回：结果留在框架列为发起会话附属的对话或标签页里，或者留在这项任务自己的运行记录里，用户用框架为它设的专门方式能看到或带回。
  - 不算交回：框架另起一个根会话，既没有记下发起方，记录里也看不到运行结果。
- 依据：
  - B01：附属对话持久挂在父会话下，用提及带回父会话，两位读者一致记 `user`。
  - B12：侧问在专门的标签页里跟踪，带摘要交回，计入。
  - C06、C09：“立即运行”的结果进这项任务自己的运行记录，记录里没有发起会话，计入。
  - B05：评审命令的结果回到会话，计入。
  - A07：“立即运行”建的是不记发起方的根会话，记录也不描述执行结果。两样都缺，第三读者不记 `user`。
  - D02 不记 `user`，理由是发布要另开开关（R2），和这一条无关。
- 写入：`fields[F25].definition.scope_rule` 把原句“用户用命令让框架新开的对话，框架跟踪它的运行，并把结果交回发起它的会话或一个汇总界面的，算框架派出的代理”句末的分号改为句号，其后插入两句：“这里的‘交回’包括：结果留在框架列为发起会话附属的对话或标签页里，或留在这项任务自己的运行记录里，用户能用框架为它设的专门方式（提及这个附属对话、切到它的标签页、查看运行记录）看到或带回。框架另起一个根会话、既没有记下发起方、记录里也看不到运行结果的，不算交回。”
- 和审读建议的出入：排除条件保留“两样都缺”，见第四节。

### 10. F11：定时任务选型号（补一句）

- 读法：
  - 定时器到点直接起的运行是另一项任务（F25、F26 仍记 `event_scheduling`），它用的型号不算本任务的型号分配。
  - 模型给定时任务指定型号的，写 value_note。
  - 主代理在任务中直接起、结果交回本任务的子任务，仍按 `model_selected_delegation` 判。
- 依据：
  - C06：自动化到点新建独立的聊天，结果不回到发起它的循环。第三读者记 `single_fixed`，“模型可以给自动化改型号”写进 value_note。

- 写入：`fields[F11].definition.scope_rule` 追加：“定时器或调度器到点直接起、另开独立会话、结果不回到发起它的循环的运行，本字段把它当作另一项任务（F25、F26 仍按 event_scheduling 记），它用的型号不算本任务的型号分配；模型建这类定时任务时为它指定型号或推理强度的，不记 model_selected_delegation，写 value_note。主代理在任务中直接起、结果交回本任务的子任务，仍按 model_selected_delegation 判。”

### 11. F23：只核对存在与否的检查（补一句）

- 读法：
  - 按路径、句柄或编号查对象存不存在的检查，和“只核对工具存不存在”一样，不算 `application_check`。
  - 服务端按用户或账户归属过滤资源的请求鉴权，不是对代理动作的检查，也不算。
- 依据：
  - C04：聊天模式下按会话句柄表查附件，查不到就报“找不到文件”。第三读者认定这是存在性查找，记 known_absent。

- 写入：`fields[F23].vocabulary[application_check].criterion` 在“只核对参数类型、必填项或工具存不存在的，不算。”之后插入：“只核对对象存不存在（按路径、句柄或编号查文件、附件或其他资源），查不到就报错、不按允许或禁止范围判断的，同样不算。服务端按用户或账户归属过滤资源的请求鉴权，管的是哪个用户能取哪份资源，不是代理动作的作用范围，也不算。”
