## 一、请负责人定的四条

### 1. R2：编进核心的官方处理器算不算“默认在用”

- 情况：A06、A17 把官方的处理器直接编进核心，内部走的却是插件或钩子的注册接口，默认会触发。两位编码者在这两个配置的 F31 `in_use_by_default` 里都记了这些阶段，在 F29 里又都按“内置”没有记 `plugin_api` 在用；两人在这里没有分歧，是甲在 A06 的备注里指出同一批内容在两个字段判法相反，并写明“若口径要求只算独立扩展包，这两项应改为空”。A01、A09 是界线的另一侧（能单独停用的官方扩展包），两人都记了在用。0.5 的 R2 只对工具写了界线。所以这一条改的是两位编码者一致的判法，不是分歧。
- 推荐（已采纳）：钩子处理器和工具用同一条界线。编进核心、不能单独停用或替换的处理器，即使内部走注册接口、默认会触发，也不算默认在用，value_note 写一句；能单独停用或替换的官方扩展包挂的处理器、默认配置里已写好的钩子才算。理由：F29、F31 对同一批内容判法一致；“能否单独停用或替换”在代码和文档里查得到。
- 另一案（未采纳）：F31 只看默认会不会触发，编进核心的也算。它能反映“框架自己靠钩子搭成”这一事实，代价是 F29、F31 对同一批内容判法相反。这一事实仍可以从 value_note 里读到。

### 2. R2 与 R3 的界线：经产品自己的扩展点装一个插件算哪一档

- 情况：A05 的插件能带来斜杠命令（一种提示模板）。甲按 R2“往默认开放的扩展点里添加内容”把它记进 F30 的取值；乙看到同一机制，按 R3 第三档“另装东西”只写了“可选：”。两条总则对“装一个插件”都说得通。
- 推荐（已采纳）：经产品自己默认开放的扩展点装进来的扩展包（放进扩展目录、用产品自带的安装命令或市场装一个插件）算添加内容：扩展点算开放，扩展包能带来的形式计入取值，不进 `in_use_by_default`。R3 第三档的“另装东西”只指产品扩展点之外的软件（另一个程序、系统依赖、另一个版本或发行包）。装完还要另开一个总开关才生效的，仍算改设置。理由：和 F29 一直以来的记法一致（放一个插件文件就算扩展点开放）。
- 另一案（未采纳）：凡要安装的都算“另装东西”。代价是同一个扩展点在 F29 里算开放、在 F30 里不算。

### 3. F04：目标停下等用户恢复算不算“升级人工”

- 情况：F04 是第一批里一致率下降的字段（50%），目标续跑失败后停下等人这一种情形占了分歧的一半（A02、A17、C02，多数是一方没找到这条路径）。找到的一方也在备注里问：框架没有主动提问、要用户自己下恢复命令，算不算“请用户做一个决定”；恢复时其实是带着续跑提示的新一轮，算不算“从原处接着走”（A05、A17、C02 的甲）。A10 是另一种：运行以失败结束后界面问重试还是放弃，甲记了，乙按“这次运行已结束”排除。
- 推荐（已采纳）：沿用 0.5 已定的那一句，并把判法说清。按用户看到的行为判，不按底层那一次运行是否已经结束判：框架按自己的规则停止自动推进，并留下一个待答的选择或一个可恢复的任务状态（受阻或暂停的目标、挂起的运行、重试或放弃的询问），用户一步确认或恢复后，原任务带着原有历史接着做、不必重述任务的，记 `escalate_to_human`，怎样恢复写 value_note。只显示错误、用户要自己重新发消息说明任务的，不记。用户要下一条恢复命令才继续的也算，这条命令恢复的是框架留下的任务状态，不按 R3 第二档排除。
- 另一案（未采纳）：只收框架主动提问、同一次运行挂起等待的情形。它更窄、更好判，但要推翻 0.5 里负责人已定的一句，而且“底层运行是否结束”要读到很深的实现才分得清，两位编码者在 A10 上正是在这里分开的。

### 4. F13：“定位起点”和“逐类解释”的界线

- 情况：这条界线仍是问得最多的。甲在 9 个配置上写了备注，A08、A09 两个配置上两人取值不同。具体有三种：压缩条目除了划出起点，还让更早的某一类条目整类不发（A08）；删段的条目只在压缩发生之后才会出现（A06）；转换层的事件类型里登记了控制条目，常规回合里遇不到，或者这一层根本不读它（A05、A07）。
- 推荐（已采纳）：
  1. 定位起点只指一刀切：某个位置之前的一概不发（或整段换成一条摘要），之后的照原样发；位置可以在几个边界里选，退回更早一个边界也算。
  2. 控制条目让同一侧的条目有的发、有的不发（按类型或按编号删去一部分、留下相邻的），就是逐类解释。
  3. 按代码判，不按某一轮里有没有遇到判：这类控制条目在默认配置下会自己产生，构造请求的代码遇到它就照此处理的，就算；条目类型只是登记在册、代码对它不作处理的，不算。
- 另一案（未采纳）：只要被删的内容都在最近一次压缩边界之前，一律算定位起点。它省事，但会让更多配置落进顺序消息，这个字段的区分度下降。

|---|---|---|

| R2、R3 装扩展包 | 扩展包经扩展点装进来、但自己还要另装系统依赖才能用时，R2 算添加内容，R3 算第三档 | R2 补一句：扩展包本身还要另装扩展点之外的软件、设环境变量或换账户档位才能用的，按 R3 第三档处理 |
| F04 `framework_input_repair` | 每次都修剪工具名的空白、不修就找不到工具时，“必要修正”和“每次都做的规范化不算”两句相反 | 改成按“这次调用不修会不会失败”判：免于校验失败、解析失败或找不到工具的修正才收；不做也不会失败的规范化不算 |
| F04 `escalate_to_human` | “用户一步确认或恢复”和原有的“重新登录后接着走也算”对不上，登录不止一步 | 改成“用户按提示确认、恢复或补上凭据后” |
