# 第三批正式编码记录（码本 fields-0.7，十个此前没有编过的工具）

这一页记录第三批正式编码的做法、两位编码者的一致程度、随后的交叉核对，以及结果能说明什么、不能说明什么。逐字段的分歧随时可以复算：

```bash
python3 studies/harness-quantification/compare_codings.py
```

编码文件在 `data/codings/` 下。它们是两位编码者各自独立的初稿，没有人工裁决，不是对任何工具的评分，也不进入方法报告正文。前两批的记录见 [`batch-1.md`](batch-1.md)、[`batch-2.md`](batch-2.md)，三轮试编码的经过见 [`../pilot/round1.md`](../pilot/round1.md)、[`../pilot/round2.md`](../pilot/round2.md)、[`../pilot/round3.md`](../pilot/round3.md)。

## 怎样做的

- 对象：10 个配置（`data/rounds/batch-3.json`）：A03 Gemini CLI、A11 Kilo Code、B01 Cursor、B02 GitHub Copilot、B17 Avante.nvim、C03 Agent Zero、C06 Open WebUI、C10 NanoClaw、D01 Dify、D04 SWE-agent。名单由负责人 2026-11-12 确认。这十个工具以前没有编过，也没有参与过码本的任何一次修订。
- 配置记录：十份都是这一批新起草的（Claude Sonnet 5.5，只查官方资料和钉住提交的源码）。入口、版本、登录方式和环境前提由负责人 2026-11-12 逐项确认，各记录里写明。几处要知道的前提：Gemini CLI 用付费 API 密钥登录；GitHub Copilot 取 VS Code 里默认的 Copilot harness；Open WebUI 接本机 Ollama、不钉型号；Dify 取新 Agent（标着 beta）；NanoClaw 的沙箱镜像按钉住的源码在本机构建；SWE-agent、Avante.nvim、NanoClaw 钉的是主分支当时的提交，不是正式标签。
- 记录的复核：编码前，十份记录各由另一位读者对照快照复核过默认工具、默认开关、默认自发的模型请求和所选入口的执行位置。原定的读者是 Kimi K3.1 Pro，当时派不出去，负责人 2026-11-13 定改由 GPT-6.1 Sol 复核。对不上的地方，九份由 Claude Sonnet 5.5 逐条核实后改进记录，Kilo Code 那一份由 Claude Opus 5.5 核实并落实；改动写在各记录的 `note` 里，编码期间没有再改。这样一来，复核记录的读者和编码者 `gpt` 是同一个型号，落实 Kilo Code 那一份的和编码者 `opus` 是同一个型号；它们是互不相干的独立运行，但这一层重合要记在这里。
- 码本：`data/schema/fields.json` 的 `fields-0.7`，36 个字段，十条跨字段总则（R1–R10）。它是第二批之后的小修订，改了总则 R2、R3、R8 和 F02、F20、F23、F30 的写法。
- 任务卡：两位编码者都用 `coding-card-v8`。
- 编码者 `opus`：Claude Opus 5.5。编码者 `gpt`：GPT-6.1 Sol，型号按派活时请求的型号记录，运行环境没有回报实际型号。
- 材料：两位编码者都不联网，只读同一份按配置记录钉的提交取下的源码快照（含官方文档导出）。三处要说明：
  - Cursor 闭源，快照里只有官方文档导出。`opus` 在这个配置上记了 34 个“低”和 2 个“未知”，`gpt` 记了 31 个“低”和 5 个“未知”。
  - GitHub Copilot 的代理循环在随包的专有运行时里，没有公开源码；快照里是 VS Code 一侧的适配代码、工具名单和官方文档。`opus` 记了 6 个“低”、30 个“中”，`gpt` 记了 23 个“低”、9 个“中”、4 个“高”。
  - NanoClaw 的主循环交给容器里的 Claude Code 去跑，那一层不在快照里。型号、预算和上下文构造三个字段（F11–F13）两位编码者都记“未知”。
- 两位编码者互不可见。每个配置分三段（字段组 ABC、DEF、GHI），一段一次独立运行，共 60 次；每段交回后由 `pilot/parts.py check` 检查，再合并。交回的 60 段都通过了检查。有一段要说明：`gpt` 的 Gemini CLI ABC 段，编码者把结果写进了运行环境的输出目录、没有写到约定的位置，任务因此被标成“没有改动”。文件原样取回后通过检查，内容没有动过。第二批有过同样的一次。
- 都只读公开资料，不安装、不运行被研究的工具。

## 一致率

一致率是“两位编码者状态和取值都相同的字段数 ÷ 36”，没有做随机一致的校正；每个配置只有一对编码者。

| 配置 | 一致 | 取值不同 | 状态不同 |
|---|---|---|---|
| A03 Gemini CLI | 86% | 5 | 0 |
| A11 Kilo Code | 94% | 2 | 0 |
| B01 Cursor | 69% | 8 | 3 |
| B02 GitHub Copilot | 75% | 9 | 0 |
| B17 Avante.nvim | 92% | 3 | 0 |
| C03 Agent Zero | 75% | 9 | 0 |
| C06 Open WebUI | 67% | 7 | 5 |
| C10 NanoClaw | 75% | 7 | 2 |
| D01 Dify | 78% | 6 | 2 |
| D04 SWE-agent | 92% | 3 | 0 |

**合计。** 360 个“字段 × 配置”里 289 个一致（80.3%），59 个取值不同，12 个状态不同。一致的 289 个里，278 个是取值相同，6 个是两人都记“不适用”（Dify 和 SWE-agent 的 F26–F28），5 个是两人都记“未知”（Cursor 的 F12、F35，NanoClaw 的 F11–F13）；两人都记未知只说明状态相同，背后没有共同的证据。

可以对照的两个数：第三次试编码也是在当时没见过的十个配置上做的，按 `fields-0.4`，一致率 83.6%；第二批在参与过修订的十个配置上是 86.4%。

**按字段看。** 十个配置上全部一致的有 7 个字段：F01、F02、F11、F18、F21、F22、F29。一致最少的是 F17（50%），其次是 F04、F05、F31、F32、F34（各 60%），再次是 F06、F10、F15、F16、F20、F28、F30、F33（各 70%）。

**分歧的形状。** 71 处不一致里，48 处在集合字段上：27 处是 `gpt` 比 `opus` 多记了成员，15 处是 `opus` 多记，6 处互有出入；7 处在单选字段上（F05 三处，F34 两处，F07、F09 各一处）；其余 16 处和状态有关：

- 8 处是一方记“未知”、另一方给了判断。其中 7 处是 `gpt` 记未知：4 处因为闭源（Cursor 的 F05、F13、F24，NanoClaw 的 F20），3 处因为词表里没有合适的取值（Open WebUI 的 F34，Dify 的 F16、F34）。1 处是 `opus` 记未知（NanoClaw 的 F28）。
- 4 处是一方记“已知不存在”、另一方给了取值（GitHub Copilot 的 F12，Dify 的 F31、F35，SWE-agent 的 F30；前三处是 `opus` 记不存在）。
- 4 处在 Open WebUI 的多代理字段（F25–F28）上：`opus` 认为码本和配置记录在这里说法冲突，记了“未知”；`gpt` 按配置记录记“已知不存在”和“不适用”。详见下文。

有 7 处，一方确认的成员正好写在另一方的“疑似成员”里。

**状态。** `opus` 记已知 322、已知不存在 22、不适用 6、未知 10；`gpt` 记已知 318、已知不存在 21、不适用 9、未知 12。

**把握程度。** `opus` 记高 149、中 155、低 40；`gpt` 记高 225、中 57、低 57。`opus` 的“低”都在 Cursor 和 GitHub Copilot 上；`gpt` 的“低”除这两个配置外，还有 3 个在 NanoClaw 上。`opus` 有 20 处用了“疑似成员”，`gpt` 有 5 处。

**子维度。** 两人都已知取值时才比较子维度，一共比较 281 个，67 个不一致，其中 11 个是一方留空（`opus` 6 个、`gpt` 5 个）。不一致较多的是 F31（31 个里 12 个）、F32（21 个里 7 个）、F11（11 个里 5 个）、F12（24 个里 5 个）、F30（12 个里 5 个）、F33（11 个里 5 个）。

**词表补充建议。** 6 条，`opus` 1 条、`gpt` 5 条，列在“编码者和读者提出的口径疑问”一节末尾。

## 交叉核对

做法和前两批相同，任务卡也是同一张：

- 每个配置一位读者，一次独立运行，共 10 次。读者是 Kimi K3.1 Pro，型号按派活时请求的型号记录，和两位编码者都不同，和前两批的读者相同。
- 读者只拿到两人主取值或状态不同的 71 个字段，两位编码者写成“甲”“乙”，每个配置随机对应，读者不知道谁是谁。
- 读者不联网，读同一份快照、配置记录和码本里相关字段的定义，不重新编码。
- 一个字段里差了几项就分几条，每条归入一类：一方没提这个机制；两人看到同一机制、归法不同；所取前提不同；材料不足；其他。
- 只对“一方没提”的条目回到快照里核对两件事：这个机制在钉住的版本里在不在；按配置记录的入口和环境前提，它在不在用户不改设置就生效的路径上。

任务卡和逐条结果在 [`batch-3/`](batch-3/)。

71 个有分歧的字段拆成 93 条：

| 类别 | 条数 |
|---|---|
| 两人看到同一机制，按码本归到了不同地方 | 59 |
| 一方记入，另一方完全没提 | 21 |
| 材料不足，一方记未知或疑似，另一方做了判断 | 8 |
| 所取前提不同 | 5 |
| 其他 | 0 |

“一方没提”的 21 条里，`gpt` 记入、`opus` 没提的 12 条，`opus` 记入、`gpt` 没提的 9 条。读者回查的结果：21 条都在钉住的版本里；16 条在默认路径上，5 条要用户另行操作才生效。

按配置：

| 配置 | 一方没提 | 归法不同 | 材料不足 | 前提不同 |
|---|---|---|---|---|
| A03 Gemini CLI | 1 | 5 | 1 | 0 |
| A11 Kilo Code | 0 | 2 | 0 | 0 |
| B01 Cursor | 3 | 6 | 6 | 0 |
| B02 GitHub Copilot | 4 | 7 | 0 | 0 |
| B17 Avante.nvim | 2 | 3 | 0 | 1 |
| C03 Agent Zero | 1 | 10 | 0 | 0 |
| C06 Open WebUI | 2 | 9 | 0 | 4 |
| C10 NanoClaw | 4 | 6 | 1 | 0 |
| D01 Dify | 3 | 7 | 0 | 0 |
| D04 SWE-agent | 1 | 4 | 0 | 0 |

分歧成串出现的几处：

- **对外的接口算不算、算哪一种**（F31、F32、F33，合起来 17 条）。官方 SDK 或服务接口的事件流里只供观察的回合事件，算不算挂了处理器的事件点（Cursor、GitHub Copilot、Dify、Open WebUI）；所选入口拉起的本机服务要凭设置界面里复制出来的令牌或登录令牌访问，算不算“不另配凭据”（Agent Zero、Open WebUI）；要另装的官方 SDK、同一部署里另一种应用形态开放的入口，算不算所选入口直接开放（Cursor、Gemini CLI、Dify）。
- **F30**（8 条）。技能和提示模板存在数据库里、不在文件系统目录里，算不算技能目录和提示模板（Open WebUI）；账户级的系统提示算不算项目规则（Open WebUI）；按名选用的整套角色模板、用启动参数选的整份配置文件，归角色模板还是别的（NanoClaw、SWE-agent）；配置里写的启动命令和工具包的安装脚本由框架执行，算不算随指导装载的可执行项（SWE-agent、NanoClaw）。
- **F17**（7 条，6 条是归法不同）。压缩产生的摘要块、逐回合记下的型号配置，算独立的控制条目还是消息记录的一部分（Avante.nvim、Agent Zero）；超长的工具结果另存文件、原文仍留在记录里（Agent Zero，前两批都问过）；待发文件的暂存目录、技能的版本快照、附件的对象存储各算哪一类（NanoClaw、Open WebUI、Dify）。
- **F04**（6 条，5 条是一方没提）。执行前的小修整：把放错字段的参数挪过去、把非字符串内容先编码、过滤无效的按钮（Avante.nvim 两条、NanoClaw 一条）；出错后留给用户的“继续”入口（Cursor、GitHub Copilot）；显式支持的工具别名算不算修整工具名（Avante.nvim）。
- **到点自己开跑的任务算不算多代理**（6 条）。Open WebUI 默认开着的自动化到点会新建一个聊天、跑完整的工具循环。`opus` 认为这符合码本说的“定时器直接起的独立代理运行”，但配置记录写着不启用子代理、校验又不许此时记“有”，于是 F25–F28 都记了未知；`gpt` 按配置记录记不存在。读者把这 4 条都归为“前提不同”。Agent Zero 的调度任务在 F27、F28 上是同一类问题。
- **只有文档、看不到实现**。8 条“材料不足”里 6 条在 Cursor 上（F05、F10、F13 各 1 条，F24 3 条）：一方按文档的措辞推断了取值，另一方记未知或放进疑似。另 2 条是 Gemini CLI 的官方 SDK 文档没写怎样驱动（F32），和 NanoClaw 的后台子代理结果怎样交回（F28）。
- **容器里的服务**（F34，4 条里 3 条）。靠容器的重启策略或容器内的进程管理器维持的服务，记本机服务、后台守护，还是词表缺一项（Agent Zero、Open WebUI、Dify）。`gpt` 在两个配置上因此记了“未知”并提了词表建议。
- **F05**（4 条）。前端和执行核心之间隔着两层时取哪一层（GitHub Copilot、NanoClaw、Cursor）；核心由前端拉起成子进程、却走本机端口（Kilo Code，第二批问过）。

**对读者结果的抽查。** “一方没提”的 21 条又由 Claude Sonnet 5.5 逐条对照快照核了三件事（两次独立运行，各看一部分配置；不重新编码，也不改读者的结果）：

| 核什么 | 结果 |
|---|---|
| 读者说另一方“完全没提” | 21 条都属实；其中 12 条，另一方在同一字段写了相近的另一条路径 |
| 读者引的位置找得到、说的是这个机制 | 19 条对；2 条引得不全 |
| 读者对“是否在默认路径上”的判断有没有依据 | 18 条有依据；1 条从所引位置看不出；2 条相反 |

- 判断相反的 2 条，读者都判成了默认生效：
  - Avante.nvim 把放错字段的参数挪正（F04）。这段修整只在工具名是两个兼容别名时才走到，默认注册给模型的是另一个同类工具，不经过它。
  - Dify 的附件存进对象存储（F17）。新 Agent 聊天的文件上传默认关着，要用户先打开。
- 看不出的 1 条：NanoClaw 角色模板带的工具服务和任务脚本（F30）。配置记录选的是空白代理，模板要在向导里另选，更像要用户另行操作。
- 引得不全的 2 条（Agent Zero 的 F27、NanoClaw 的 F10）：机制和默认判断都成立，读者只引到了一部分代码。
- “另一方写了相近路径”的 12 条仍算一方没提，但它们离“归法不同”很近：另一方不是没看这一块，而是看了旁边的一条路径。第二批的抽查里这样标的只有 1 条；两批的抽查者是同一个型号的不同运行，标法的松紧可能不一样，这两个数不宜直接比。

所以上面“16 条在默认路径上”应读作读者的判断：抽查支持其中 13 条，3 条存疑或相反。读者判“要用户另行操作”的 5 条，抽查都支持。“归法不同”“材料不足”和“前提不同”的 72 条没有抽查。

这一步的局限：每条只有一位读者判；只看了两人有分歧的字段，两人一致的 289 个没有回查；Cursor 和 GitHub Copilot 的位置只能在文档导出和宿主一侧的源码里核。

## 能说明什么

- 这是正式编码里第一次用没参与过修订的配置。一致率 80.3%，比第二批在见过的配置上低 6 个百分点，也比第三次试编码在当时的新配置上（83.6%）低。码本在新配置上的一致程度，应当看这个数，不看前两批。
- 一致率随工具的形态分成两截。开源、本机运行的终端工具和编辑器插件四个（Gemini CLI、Kilo Code、Avante.nvim、SWE-agent）合起来 91%；另外六个合起来 73%：闭源的 Cursor、循环在专有运行时里的 GitHub Copilot，以及跑在容器里、通过网页或消息渠道使用的 Agent Zero、Open WebUI、NanoClaw、Dify。码本前几次修订依据的大多是前一类工具。
- 这一批“归法不同”远多于“漏看”（59 条对 21 条；第二批 39 条对 30 条）。抽查里又有 12 条“漏看”其实是另一方看了相邻的路径。两位编码者看到的事实大体相同，分歧主要在码本没有写到的情形上：服务形态的产品怎样对应“入口”“前端”“本机服务”这些为本机工具写的概念，存在数据库里的技能和提示怎样对应“目录”“文件”，只有文档时记取值还是记未知。
- 漏看的不对称比前两批都小：`gpt` 找到、`opus` 没提的 12 条，反过来 9 条（第二批 18 条对 12 条）。抽查里默认与否存疑或相反的 3 条，`opus` 记入的 2 条，`gpt` 记入的 1 条。
- 第二批之后定的几条口径（`fields-0.7`），这一批没有起新的分歧：F02 十个配置全部一致；同一份技能两种调用方式的问题没有再出现。但这十个工具里没有模型现写的工作流脚本，也没有模型自己能启用的默认关闭扩展，这几条大多没有被用到，谈不上检验过。F20 的幂等键在 Open WebUI 和 NanoClaw 上仍有分歧，见下一节。
- Open WebUI 是一致最低的配置（67%），12 个分歧字段里 4 个出在自动化算不算多代理这一件事上，另有 2 个（F30、F34）出在数据库里的技能和提示、容器里的服务上。Cursor（69%）的 11 个分歧字段里，4 个带“材料不足”的条目（共 6 条）。
- 复核配置记录的读者和编码者 `gpt` 是同一个型号。记录的措辞可能因此更接近 `gpt` 的读法；这一批的数据看不出这一点有多大影响，也排除不了。
- 一致不等于正确，不一致也不说明哪一方错。交叉核对只给分歧分了类、回查了漏看的事实，没有裁决取值。
- 样本只有 10 个配置、一对编码者，没有做随机一致校正，不足以给单个字段的可靠性下结论。

## 编码者和读者提出的口径疑问

下面的问题来自 `opus` 交回时的说明、两位编码者写在字段里的备注，以及交叉核对里读者判为“归法不同”“材料不足”“前提不同”的 72 条。整张表由 Claude Sonnet 5.5 摘出：`opus` 的交回说明和读者的 72 条是通读的，两份字段备注（合起来约 600 条）是按关键词摘读的，没有逐行通读，可能有漏。这里不作裁决；编码期间提出的问题一律没有答复，免得两位编码者不再独立。

行内标记：没有标记的，是编码者在交回说明或字段备注里明写拿不准、码本没说的；“（读者）”是交叉核对里读者指出两人读法不同、编码者自己没写成疑问的；“（归纳）”是几个配置上做法不一致、由摘录者归纳的；“（第二批已问）”是第二批的口径疑问表里已有同类问题。

| 字段 | 疑问 |
|---|---|
| 总则 R2、R3 | 管理员或用户在设置里加一条外部工具服务（MCP），算添加内容还是改设置：Open WebUI、Agent Zero 按添加内容计入工具协议转换，Dify 因为还要在 Agent 配置页按名挂上，只写“可选”（归纳，F10）；Dify 的 F15 里“先建知识库、再在配置页勾选挂上”，一位编码者按添加内容计入、另一位按按名启用只写可选，编码者自己也记下它和 Dify 的 MCP 读法不一致（F15，读者）；用启动参数指向随仓库的整份配置文件才启用的路径，算第二档还是添加内容（SWE-agent，涉及 F01 的重试代理、F29 的用户脚本、F30 的 YAML 配置）；官方 /loop 这类要显式输入斜杠命令的入口，算不算所选入口直接开放（Cursor，F33，读者）；工作流里放一个 Agent 节点才能触发定时或外部事件、或才有委派工具，算不算默认可用（Dify，F25、F33）；默认注册的 run_python 要本机另装 Docker 才能跑，算默认还是需额外安装（Avante.nvim，F06 只写备注、F23 却计入，同一位编码者两处读法不同，归纳） |

| 总则 R6、R7 | 闭源产品只有文档、文档没写某一项时，怎么记：推断取值、known_absent、unknown 还是 null（Cursor 的 F12、F13、F23，Copilot 的 F12、F23，NanoClaw 的主循环在快照外的 Claude Code 里；3 个配置；编码者明写“另一读法是 unknown”“也许该写 null，码本可单说一句”；两位编码者在 Cursor 的 F23 上一个记 absent、一个整层 null，归纳）；旧发布说明提到的功能，当前文档的同一页没有列出，按“当前文档已有覆盖而没有该项”放疑似，还是按旧说明延续（Cursor 的语义检索，F15，读者） |
| 总则 R10 | 实现和设计意图不一致时按实现判：SWE-agent 的撤销编辑工具按实现取不到文件历史，记 known_absent，按设计意图应记工作区快照（F20；另一位编码者也写“建议复核”）；后端有执行代码、前端常量写死关闭的功能，按总则 R5“同一发行版官方文档里的入口”还是按 R10“从来不会发出的模式”（Dify 的内容审核扩展，F31，读者）；配置记录称某功能在免费档不可用、宿主源码却没有档位分支，按代码计入（Copilot 的技能，F30，编码者按 R1、R10 处理并写明） |
| F02 | 单条目标加状态、目标未完成时不让结束，算不算计划（Agent Zero，记为只在提示里写）；“无工具回复而待办没做完就提醒续发”的规则归 F02 的可执行流程约束还是归 F03（Avante.nvim，记为结构化任务表） |

| F07、F08、F09 | F07：状态存在独立数据库、但只有调用核心的 API 层读写，记 client 还是 state_service（Dify，编码者和读者都提）；界面和循环在同一个 Lua 插件同进程、靠模块分层判（Avante.nvim）；Agent Host 加运行时整体算执行一侧还是独立状态服务（Copilot）；本机数据库存对话历史、服务端是否另持权威副本文档没写（Cursor）；两方分别写的邮箱文件算不算状态服务（NanoClaw）。F08：容器里每次运行创建的专用仓库目录，是否另记 working_directory，容器自带文件系统是否另记 filesystem（SWE-agent，读者；另一位编码者写“可能需要再明确”）。F09：独立的 BYOK 回环代理和运行时内部的三种消息格式，哪个决定模型调用抽象类别（Copilot，读者） |

| F11 | 语音识别（Whisper）、嵌入这类不是对话型号的模型，算不算本字段的“型号”（Open WebUI）；辅助型号取决于快照外的库（Dify 的压缩摘要）或闭源核心（NanoClaw），记已确认部分还是未知（与第二批“辅助型号是编译默认值、主型号由服务端决定”相近） |
